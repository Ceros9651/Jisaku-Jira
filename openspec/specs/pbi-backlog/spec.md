# pbi-backlog Specification

## Purpose
個人開発のスクラムで使うプロダクトバックログを管理する。PBI を追加順の安定した ID（`PBI-<番号>`）で識別し、優先順位に沿って手動で並べ替えられるようにする。

## Requirements

### Requirement: PBI の作成
システムは、タイトルを入力して PBI を作成できる機能を提供 SHALL する。タイトルは前後の空白を除いて1文字以上でなければならない。説明とストーリーポイントは任意とする。作成された PBI のステータスは `To Do` とし、選んでいるプロジェクトのバックログの末尾に追加する。

#### Scenario: タイトルだけで作成する
- **WHEN** ユーザーがタイトル「ログイン画面を作る」を入力して作成する
- **THEN** 選んでいるプロジェクトのバックログの末尾に、タイトル「ログイン画面を作る」、ステータス `To Do`、説明とストーリーポイントが空の PBI が追加される

#### Scenario: タイトルが空のときは作成しない
- **WHEN** ユーザーがタイトルを空、または空白だけにして作成しようとする
- **THEN** PBI は作成されず、タイトルが必要であることが表示される

#### Scenario: 他のプロジェクトには追加されない
- **WHEN** プロジェクト「Web」と「Tool」があり、「Tool」を選んでいる状態で PBI を作成する
- **THEN** PBI は「Tool」の一覧にだけ表示され、「Web」の一覧には表示されない

### Requirement: PBI の ID 採番
システムは、PBI を作成した順に `PBI-1`, `PBI-2`, `PBI-3`, … の ID を付与 SHALL する。番号はすべてのプロジェクトを通した連番で、それまでに発行した最大の番号に1を足した値とする。一度付与した ID は変更せず、PBI やプロジェクトを削除してもその番号を再利用しない。

#### Scenario: 最初の PBI
- **WHEN** PBI が一度も作られていないバックログで PBI を作成する
- **THEN** その PBI の ID は `PBI-1` になる

#### Scenario: 続けて作成する
- **WHEN** `PBI-1` と `PBI-2` がある状態で PBI を作成する
- **THEN** 新しい PBI の ID は `PBI-3` になる

#### Scenario: 削除した番号は欠番になる
- **WHEN** `PBI-1`〜`PBI-3` がある状態で `PBI-3` を削除し、その後 PBI を作成する
- **THEN** 新しい PBI の ID は `PBI-4` になり、`PBI-3` は再び使われない

#### Scenario: 並べ替えても ID は変わらない
- **WHEN** `PBI-2` をバックログの先頭に移動する
- **THEN** 移動した PBI の ID は `PBI-2` のままで、他の PBI の ID も変わらない

#### Scenario: プロジェクトをまたいで通し番号になる
- **WHEN** プロジェクト「Web」に `PBI-1` と `PBI-2` がある状態で、「Tool」を選んで PBI を作成する
- **THEN** 「Tool」に作られた PBI の ID は `PBI-3` になる

#### Scenario: 削除したプロジェクトの番号も再利用しない
- **WHEN** プロジェクト「Tool」に `PBI-3` と `PBI-4` だけがある状態で「Tool」を削除し、別のプロジェクトで PBI を作成する
- **THEN** 新しい PBI の ID は `PBI-5` になる

### Requirement: バックログ一覧の表示
システムは、選んでいるプロジェクトのすべての PBI をバックログの並び順で一覧表示 SHALL する。各行には ID、タイトル、ステータス、ストーリーポイントを表示する。一覧の見出しにはプロジェクトの名前を表示し、その上部には選んでいるプロジェクトの PBI の件数とストーリーポイントの合計を表示する。

#### Scenario: 一覧を開く
- **WHEN** ユーザーがバックログ画面を開く
- **THEN** 選んでいるプロジェクトのすべての PBI がバックログの並び順で、ID・タイトル・ステータス・ストーリーポイントとともに表示される

#### Scenario: 件数と合計
- **WHEN** 選んでいるプロジェクトにストーリーポイント 3、5、未設定の PBI が3件あり、他のプロジェクトに SP 8 の PBI が1件ある
- **THEN** 一覧の上部に件数 3 とストーリーポイント合計 8 が表示される

#### Scenario: PBI がないとき
- **WHEN** 選んでいるプロジェクトに PBI が1件もない
- **THEN** PBI がないことと、PBI を作成する操作が表示される

### Requirement: PBI の詳細表示と編集
システムは、PBI を選択するとその ID、タイトル、説明、ステータス、ストーリーポイントを表示し、ID 以外の項目を編集できるように SHALL する。編集でもタイトルは前後の空白を除いて1文字以上でなければならない。

#### Scenario: タイトルと説明を編集する
- **WHEN** ユーザーが `PBI-2` を開き、タイトルと説明を変更して保存する
- **THEN** `PBI-2` のタイトルと説明が更新され、ID とバックログ上の位置は変わらない

#### Scenario: タイトルを空にして保存しようとする
- **WHEN** ユーザーが編集中にタイトルを空にして保存しようとする
- **THEN** 変更は保存されず、タイトルが必要であることが表示される

### Requirement: ステータス
PBI のステータスは `To Do`、`In Progress`、`Done` のいずれかで SHALL ある。ユーザーは一覧と詳細のどちらからでもステータスを変更できる。

#### Scenario: 一覧からステータスを変更する
- **WHEN** ユーザーが一覧で `PBI-1` のステータスを `In Progress` に変更する
- **THEN** `PBI-1` のステータスが `In Progress` になり、一覧の表示に反映される

### Requirement: ストーリーポイント
PBI のストーリーポイントは未設定、または 0 以上の整数で SHALL ある。それ以外の値は保存しない。

#### Scenario: ストーリーポイントを設定する
- **WHEN** ユーザーが `PBI-1` のストーリーポイントに 5 を入力して保存する
- **THEN** `PBI-1` のストーリーポイントが 5 になる

#### Scenario: 不正な値
- **WHEN** ユーザーがストーリーポイントに -1 や 2.5 や文字を入力して保存しようとする
- **THEN** 値は保存されず、0 以上の整数が必要であることが表示される

#### Scenario: 未設定に戻す
- **WHEN** ユーザーがストーリーポイントの入力を空にして保存する
- **THEN** ストーリーポイントは未設定になる

### Requirement: PBI の削除
システムは、確認を経たうえで PBI を削除できる機能を提供 SHALL する。削除した PBI は一覧から消え、他の PBI の ID と並び順は変わらない。

#### Scenario: 確認して削除する
- **WHEN** ユーザーが `PBI-2` の削除を選び、確認で削除を選ぶ
- **THEN** `PBI-2` が一覧から消え、残りの PBI は元の順序のまま表示される

#### Scenario: 確認で取り消す
- **WHEN** ユーザーが `PBI-2` の削除を選び、確認で取り消す
- **THEN** `PBI-2` は削除されない

### Requirement: バックログの手動並べ替え
システムは、ユーザーが PBI のバックログ上の位置を、その PBI が属するプロジェクトの中で変更できるように SHALL する。並べ替えはポインター操作（ドラッグ）とキーボード操作の両方でできなければならない。並べ替えても他のプロジェクトの並び順は変わらない。並べ替えの結果は保存され、再読み込み後も保たれる。

#### Scenario: ドラッグで並べ替える
- **WHEN** 並び順が `PBI-1`, `PBI-2`, `PBI-3` のときに、ユーザーが `PBI-3` を先頭へドラッグする
- **THEN** 並び順が `PBI-3`, `PBI-1`, `PBI-2` になる

#### Scenario: キーボードで並べ替える
- **WHEN** ユーザーがキーボードで `PBI-1` を1つ下へ移動する操作をする
- **THEN** `PBI-1` と直後の PBI の順序が入れ替わる

#### Scenario: 並び順は再読み込み後も保たれる
- **WHEN** ユーザーが並べ替えた後にページを再読み込みする
- **THEN** 並べ替えた後の順序で一覧が表示される

### Requirement: ステータスのラベル表示
システムは、一覧と詳細パネルのステータスを、同じ見た目のラベルとして表示 SHALL する。ラベルは文字の幅に合わせ、ステータス名（To Do / In Progress / Done）を文字で示す。色は To Do＝灰、In Progress＝青、Done＝緑の3種だけを補助に使う。変更できることを示す矢印は、行に hover したときか、ラベルに focus したときだけ表示する。ステータスは今までどおり選択肢から変更できる。

#### Scenario: 一覧ではラベルとして見える
- **WHEN** ユーザーが PBI のある一覧を、どの行にも hover せずに見る
- **THEN** 各行のステータスは文字幅のラベルとして表示され、変更の矢印は表示されない

#### Scenario: hover で変更の手がかりが出る
- **WHEN** ユーザーが一覧のある行に hover する
- **THEN** その行のステータスラベルにだけ変更の矢印が表示され、押すと選択肢から変更できる

#### Scenario: 詳細パネルでも同じ見た目
- **WHEN** ユーザーが PBI の詳細パネルを開く
- **THEN** 詳細パネルのステータスは、一覧と同じ形と色のラベルで表示される

### Requirement: 一覧の幅
システムは、デスクトップの画面幅でバックログ一覧をコンテンツ領域の幅いっぱいに表示 SHALL する。詳細パネルを開いたときは、一覧の右側にパネルを並べる。

#### Scenario: 詳細パネルを閉じているとき
- **WHEN** 幅 1440px の画面で、詳細パネルを閉じた状態の一覧を見る
- **THEN** 一覧の右端がコンテンツ領域の右端（画面の右の余白の手前）まで届き、右側に何もない帯が残らない

### Requirement: ステータス別の SP 集計
システムは、一覧の見出しの行に、件数と SP 合計に加えて、ステータスごとの SP 合計を表示 SHALL する。ステータスごとの合計は、ステータスのラベルと同じ色で区別し、どのステータスの値かを文字でも読めるようにする。集計の文字は本文に近い濃さで表示する。

#### Scenario: ステータスごとの合計
- **WHEN** 一覧に Done で SP 3、In Progress で SP 5、To Do で SP 2、To Do で SP 未設定の PBI がある
- **THEN** 見出しの行に「4 件」「10 pt」と、To Do 2・In Progress 5・Done 3 が表示される

### Requirement: 作成欄の表示
システムは、PBI の作成欄を一覧の上（見出しの下）に表示し、一覧をスクロールしても画面の上端に残るように SHALL する。作成欄は一覧の行と同じ高さの、罫線で区切った1行として表示し、塗りつぶした色のボタンを使わない。作成欄に入力して作った PBI は、一覧の末尾に追加される。

#### Scenario: スクロールしても作成欄が見える
- **WHEN** ユーザーが PBI の多い一覧を下までスクロールする
- **THEN** 作成欄は画面の上端に表示されたままで、そのままタイトルを入力して作成できる

#### Scenario: 作成欄が一覧より目立たない
- **WHEN** ユーザーがバックログ画面を開く
- **THEN** 作成欄の「作成」ボタンは枠線だけのボタンとして表示され、塗りつぶした色のボタンではない

### Requirement: 詳細パネルの見出し
システムは、詳細パネルの先頭に PBI の ID と、見出しとして読めるタイトルを表示 SHALL する。タイトルは普段は枠の無い大きな文字として表示し、hover・focus のときだけ入力欄の枠を示して、その場で編集できる。画面上のラベル「タイトル」は表示しないが、読み上げでは「タイトル」の入力欄として識別できる。ステータスとストーリーポイントは、ラベルを左、値を右に並べた行で表示する。

#### Scenario: 詳細パネルを開く
- **WHEN** ユーザーが PBI-1 の詳細パネルを開く
- **THEN** パネルの先頭に「PBI-1」と、そのタイトルが枠の無い見出しの文字として表示される

#### Scenario: タイトルをその場で編集する
- **WHEN** ユーザーが詳細パネルのタイトルを押す
- **THEN** タイトルが入力欄の枠付きで編集できる状態になり、変更して保存すると反映される
