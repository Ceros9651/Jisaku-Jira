# pbi-backlog Specification

## Purpose
個人開発のスクラムで使うプロダクトバックログを管理する。PBI を追加順の安定した ID（`PBI-<番号>`）で識別し、優先順位に沿って手動で並べ替えられるようにする。

## Requirements

### Requirement: PBI の作成
システムは、タイトルを入力して PBI を作成できる機能を提供 SHALL する。タイトルは前後の空白を除いて1文字以上でなければならない。説明とストーリーポイントは任意とする。作成された PBI のステータスは `To Do` とし、選んでいるプロジェクトのバックログの末尾に追加する。

#### Scenario: タイトルだけで作成する
- **WHEN** ユーザーがタイトル「ログイン画面を作る」を入力して作成する
- **THEN** 選んでいるプロジェクトのバックログの末尾に、タイトル「ログイン画面を作る」、ステータス `To Do`、説明とストーリーポイントが空の PBI が追加される

#### Scenario: タイトルが空のときは作成しない
- **WHEN** ユーザーがタイトルを空、または空白だけにして作成しようとする
- **THEN** PBI は作成されず、タイトルが必要であることが表示される

#### Scenario: 他のプロジェクトには追加されない
- **WHEN** プロジェクト「Web」と「Tool」があり、「Tool」を選んでいる状態で PBI を作成する
- **THEN** PBI は「Tool」の一覧にだけ表示され、「Web」の一覧には表示されない

### Requirement: プロジェクトごとの PBI の ID 採番
システムは、PBI を作成した順に、プロジェクトごとに `PBI-1`, `PBI-2`, `PBI-3`, … の ID を付与 SHALL する。番号はプロジェクトの中での連番で、そのプロジェクトでそれまでに発行した最大の番号に1を足した値とする。他のプロジェクトで発行した番号は影響しない。別々のプロジェクトに同じ番号の PBI があってよいが、1つのプロジェクトの中では番号は重複しない。一度付与した ID は変更せず、PBI を削除してもそのプロジェクトでその番号を再利用しない。

#### Scenario: 最初の PBI
- **WHEN** PBI が一度も作られていないプロジェクトで PBI を作成する
- **THEN** その PBI の ID は `PBI-1` になる

#### Scenario: 続けて作成する
- **WHEN** あるプロジェクトに `PBI-1` と `PBI-2` がある状態で、そのプロジェクトで PBI を作成する
- **THEN** 新しい PBI の ID は `PBI-3` になる

#### Scenario: 削除した番号は欠番になる
- **WHEN** あるプロジェクトに `PBI-1`〜`PBI-3` がある状態で `PBI-3` を削除し、その後そのプロジェクトで PBI を作成する
- **THEN** 新しい PBI の ID は `PBI-4` になり、そのプロジェクトで `PBI-3` は再び使われない

#### Scenario: 並べ替えても ID は変わらない
- **WHEN** `PBI-2` をバックログの先頭に移動する
- **THEN** 移動した PBI の ID は `PBI-2` のままで、他の PBI の ID も変わらない

#### Scenario: プロジェクトごとに 1 から振る
- **WHEN** プロジェクト「Jisaku-Jira-App」に `PBI-1`〜`PBI-9` があり、PBI の無い「Yarikuri」を選んで PBI を作成する
- **THEN** 「Yarikuri」に作られた PBI の ID は `PBI-1` になる

#### Scenario: 他のプロジェクトの作成は番号に影響しない
- **WHEN** 「Web」に `PBI-1` と `PBI-2`、「Tool」に `PBI-1` がある状態で、「Web」で PBI を作成し、そのあと「Tool」で PBI を作成する
- **THEN** 「Web」に作られた PBI は `PBI-3`、「Tool」に作られた PBI は `PBI-2` になる

#### Scenario: 新しく作ったプロジェクトも 1 から
- **WHEN** 他のプロジェクトに PBI がある状態でプロジェクト「Docs」を作成し、「Docs」で PBI を作成する
- **THEN** 「Docs」に作られた PBI の ID は `PBI-1` になる

#### Scenario: 削除したプロジェクトは他のプロジェクトの番号に影響しない
- **WHEN** 「Web」に `PBI-1` と `PBI-2`、「Tool」に `PBI-1`〜`PBI-4` がある状態で「Tool」を削除し、「Web」で PBI を作成する
- **THEN** 新しい PBI の ID は `PBI-3` になる

### Requirement: バックログ一覧の表示
システムは、選んでいるプロジェクトの PBI を、ステータスが `To Do` または `In Progress` の PBI を並べる一覧（以下、未完了の一覧）と、その下の Done エリアに分けて表示 SHALL する。未完了の一覧には `Done` の PBI を表示しない。どちらもバックログの並び順で並べ、各行には ID、タイトル、ステータス、ストーリーポイントを表示する。画面の見出しにはプロジェクトの名前を表示し、未完了の一覧の区画の見出しの行には、選んでいるプロジェクトの `To Do` と `In Progress` の PBI の件数と、そのストーリーポイントの合計を表示する。

#### Scenario: 一覧を開く
- **WHEN** ユーザーがバックログ画面を開く
- **THEN** 選んでいるプロジェクトの `To Do` と `In Progress` の PBI がバックログの並び順で、ID・タイトル・ステータス・ストーリーポイントとともに未完了の一覧に表示され、`Done` の PBI は未完了の一覧に表示されない

#### Scenario: 件数と合計
- **WHEN** 選んでいるプロジェクトに `To Do` でストーリーポイント 3、`In Progress` で 5、`To Do` で未設定、`Done` で 2 の PBI が4件あり、他のプロジェクトに `To Do` で SP 8 の PBI が1件ある
- **THEN** 未完了の一覧の区画の見出しの行に件数 3 とストーリーポイント合計 8 が表示される

#### Scenario: PBI がないとき
- **WHEN** 選んでいるプロジェクトに PBI が1件もない
- **THEN** 未完了の一覧の区画に PBI がないことと、PBI を作成する操作が表示され、Done エリアは表示されない

#### Scenario: 未完了の PBI がないとき
- **WHEN** 選んでいるプロジェクトの PBI がすべて `Done` である
- **THEN** 未完了の一覧の区画に未完了の PBI がないことと作成の操作が表示され、その下の Done エリアにすべての PBI が表示される。未完了の区画の件数は 0、合計は 0 になる

### Requirement: PBI の詳細表示と編集
システムは、PBI を選択するとその ID、タイトル、説明、受入条件、ステータス、ストーリーポイントを表示し、ID 以外の項目を編集できるように SHALL する。編集でもタイトルは前後の空白を除いて1文字以上でなければならない。受入条件は複数行の自由記述で、空でもよく、入力された内容をそのまま保存する。受入条件の入力欄は説明の下に「受入条件」のラベルを付けて置き、説明と同じく保存の操作で保存する。

#### Scenario: タイトルと説明を編集する
- **WHEN** ユーザーが `PBI-2` を開き、タイトルと説明を変更して保存する
- **THEN** `PBI-2` のタイトルと説明が更新され、ID とバックログ上の位置は変わらない

#### Scenario: タイトルを空にして保存しようとする
- **WHEN** ユーザーが編集中にタイトルを空にして保存しようとする
- **THEN** 変更は保存されず、タイトルが必要であることが表示される

#### Scenario: 受入条件を書いて保存する
- **WHEN** ユーザーが `PBI-2` を開き、受入条件に「- ログインできる\n- 誤ったパスワードではエラーが出る」を入力して保存する
- **THEN** `PBI-2` の受入条件がその2行のとおりに保存され、開き直しても同じ内容が表示される

#### Scenario: 受入条件だけを変更する
- **WHEN** ユーザーが詳細パネルで受入条件だけを変更する
- **THEN** 保存ボタンが押せるようになり、保存すると受入条件だけが更新される

#### Scenario: 受入条件が空の PBI
- **WHEN** ユーザーが受入条件を一度も書いていない PBI の詳細パネルを開く
- **THEN** 「受入条件」のラベルと空の入力欄が表示される

#### Scenario: 作成した PBI の受入条件
- **WHEN** ユーザーが作成欄からタイトルだけを入力して PBI を作成する
- **THEN** その PBI の受入条件は空になる

### Requirement: ステータス
PBI のステータスは `To Do`、`In Progress`、`Done` のいずれかで SHALL ある。ユーザーは未完了の一覧、Done エリア、詳細のどこからでもステータスを変更できる。ステータスを `Done` に変えた PBI はすぐに Done エリアに移り、`Done` から `To Do` または `In Progress` に変えた PBI はすぐに未完了の一覧に戻る。移ってもバックログの並び順は変わらないため、未完了の一覧に戻った PBI は、`Done` にする前と同じ前後関係の位置に表示される。

#### Scenario: 一覧からステータスを変更する
- **WHEN** ユーザーが一覧で `PBI-1` のステータスを `In Progress` に変更する
- **THEN** `PBI-1` のステータスが `In Progress` になり、一覧の表示に反映される

#### Scenario: Done にすると Done エリアに移る
- **WHEN** 未完了の一覧に `PBI-1`, `PBI-2`, `PBI-3` が並んでいるときに、ユーザーが一覧で `PBI-2` のステータスを `Done` に変更する
- **THEN** 未完了の一覧は `PBI-1`, `PBI-3` になり、`PBI-2` は Done エリアに表示される

#### Scenario: 詳細から Done にしても移る
- **WHEN** ユーザーが `PBI-2` の詳細パネルでステータスを `Done` に変更する
- **THEN** `PBI-2` は未完了の一覧から消えて Done エリアに表示され、詳細パネルは開いたまま `PBI-2` を表示している

#### Scenario: Done から戻すと元の位置に戻る
- **WHEN** バックログの並び順が `PBI-1`, `PBI-2`, `PBI-3` で `PBI-2` だけが `Done` のときに、ユーザーが Done エリアで `PBI-2` のステータスを `To Do` に変更する
- **THEN** `PBI-2` は Done エリアから消え、未完了の一覧は `PBI-1`, `PBI-2`, `PBI-3` の順になる

### Requirement: ストーリーポイント
PBI のストーリーポイントは未設定、または 0 以上の整数で SHALL ある。それ以外の値は保存しない。

#### Scenario: ストーリーポイントを設定する
- **WHEN** ユーザーが `PBI-1` のストーリーポイントに 5 を入力して保存する
- **THEN** `PBI-1` のストーリーポイントが 5 になる

#### Scenario: 不正な値
- **WHEN** ユーザーがストーリーポイントに -1 や 2.5 や文字を入力して保存しようとする
- **THEN** 値は保存されず、0 以上の整数が必要であることが表示される

#### Scenario: 未設定に戻す
- **WHEN** ユーザーがストーリーポイントの入力を空にして保存する
- **THEN** ストーリーポイントは未設定になる

### Requirement: PBI の削除
システムは、確認を経たうえで PBI を削除できる機能を提供 SHALL する。削除した PBI は一覧から消え、他の PBI の ID と並び順は変わらない。

#### Scenario: 確認して削除する
- **WHEN** ユーザーが `PBI-2` の削除を選び、確認で削除を選ぶ
- **THEN** `PBI-2` が一覧から消え、残りの PBI は元の順序のまま表示される

#### Scenario: 確認で取り消す
- **WHEN** ユーザーが `PBI-2` の削除を選び、確認で取り消す
- **THEN** `PBI-2` は削除されない

### Requirement: バックログの手動並べ替え
システムは、ユーザーが未完了の一覧で PBI のバックログ上の位置を、その PBI が属するプロジェクトの中で変更できるように SHALL する。並べ替えはポインター操作（ドラッグ）とキーボード操作の両方でできなければならない。並べ替えても他のプロジェクトの並び順は変わらず、未完了の一覧どうしの前後関係だけが変わる。Done エリアの PBI は並べ替えの対象にしない。並べ替えの結果は保存され、再読み込み後も保たれる。

#### Scenario: ドラッグで並べ替える
- **WHEN** 並び順が `PBI-1`, `PBI-2`, `PBI-3` のときに、ユーザーが `PBI-3` を先頭へドラッグする
- **THEN** 並び順が `PBI-3`, `PBI-1`, `PBI-2` になる

#### Scenario: キーボードで並べ替える
- **WHEN** ユーザーがキーボードで `PBI-1` を1つ下へ移動する操作をする
- **THEN** `PBI-1` と、未完了の一覧で直後に表示されている PBI の順序が入れ替わる

#### Scenario: Done の PBI をまたいで並べ替える
- **WHEN** バックログの並び順が `PBI-1`, `PBI-2`, `PBI-3` で `PBI-2` が `Done` のとき（未完了の一覧は `PBI-1`, `PBI-3`）に、ユーザーが `PBI-3` を未完了の一覧の先頭へドラッグする
- **THEN** 未完了の一覧は `PBI-3`, `PBI-1` になり、`PBI-2` は Done エリアに表示されたままになる

#### Scenario: Done エリアでは並べ替えられない
- **WHEN** ユーザーが Done エリアの行を見る
- **THEN** その行には並べ替えの持ち手が表示されず、ドラッグやキーボードで位置を変えられない

#### Scenario: 並び順は再読み込み後も保たれる
- **WHEN** ユーザーが並べ替えた後にページを再読み込みする
- **THEN** 並べ替えた後の順序で一覧が表示される

### Requirement: ステータスのラベル表示
システムは、一覧と詳細パネルのステータスを、同じ見た目のボタン状のラベルとして表示 SHALL する。ラベルは文字の幅に合わせ、ステータス名（To Do / In Progress / Done）を大文字に変えずに文字で示す。色は To Do＝灰、In Progress＝青、Done＝緑の3種だけを補助に使う。変更できることを示す下向きの矢印は、常にラベルの右端に表示する。ステータスは今までどおり選択肢から変更できる。

#### Scenario: 一覧ではラベルとして見える
- **WHEN** ユーザーが PBI のある一覧を、どの行にも hover せずに見る
- **THEN** 各行のステータスは「In Progress」のように大文字に変えない文字幅のラベルとして表示され、右端に変更の矢印が表示される

#### Scenario: hover で変更の手がかりが出る
- **WHEN** ユーザーが一覧のある行のステータスのラベルに hover する
- **THEN** そのラベルの地の色が少し濃くなり、矢印と合わせて押せることが分かる

#### Scenario: 押すと変更できる
- **WHEN** ユーザーが一覧のある行のステータスのラベルを押す
- **THEN** 選択肢が開き、To Do / In Progress / Done から変更できる

#### Scenario: 詳細パネルでも同じ見た目
- **WHEN** ユーザーが PBI の詳細パネルを開く
- **THEN** 詳細パネルのステータスは、一覧と同じ形と色のラベルで表示される

### Requirement: 一覧の幅
システムは、デスクトップの画面幅でバックログ一覧をコンテンツ領域の幅いっぱいに表示 SHALL する。詳細パネルを開いたときは、詳細パネルを画面の右端に貼り付けて上部ナビゲーションの下から画面の下端までの高さで表示し、一覧はその左の残りの幅いっぱいに表示する。詳細パネルの中が長いときは、パネルの中だけがスクロールする。幅 760px 以下の画面では、詳細パネルを一覧の下に表示する。

#### Scenario: 詳細パネルを閉じているとき
- **WHEN** 幅 1440px の画面で、詳細パネルを閉じた状態の一覧を見る
- **THEN** 一覧の区画の右端がコンテンツ領域の右端（画面の右の余白の手前）まで届き、右側に何もない帯が残らない

#### Scenario: 詳細パネルを開いたとき
- **WHEN** 幅 1440px の画面で、PBI の詳細パネルを開く
- **THEN** 詳細パネルは画面の右端に接し、上部ナビゲーションの下から画面の下端まで届き、一覧をスクロールしてもパネルの位置は動かない

### Requirement: ステータス別の SP 集計
システムは、各区画の見出しの行に、件数と SP 合計に加えて、その区画に含まれる PBI のステータスごとの SP 合計を表示 SHALL する。未完了の一覧の区画では `To Do` と `In Progress` の2つを、Done エリアの区画では `Done` の1つを表示し、どの区画のバッジの合計も、その区画の SP 合計と一致する。件数と SP 合計も、その区画の PBI だけで数える。ステータスごとの合計は、区画の見出しの行の右端に、ステータスのラベルと同じ色の小さなバッジで並べ、どのステータスの値かを文字でも読めるようにする。集計の文字は本文に近い濃さで表示する。

#### Scenario: ステータスごとの合計
- **WHEN** 一覧に Done で SP 3、In Progress で SP 5、To Do で SP 2、To Do で SP 未設定の PBI がある
- **THEN** 未完了の一覧の区画の見出しの行に「3 件の PBI」「7 pt」と、右端に To Do 2・In Progress 5 が表示され、Done のバッジは表示されない。Done の区画の見出しの行には「1 件の PBI」「3 pt」と、右端に Done 3 が表示される

#### Scenario: 区画のバッジの合計は区画の SP 合計と一致する
- **WHEN** 選んでいるプロジェクトに、ステータスが混ざった PBI がある
- **THEN** 各区画の右端のバッジの値を足すと、その区画の見出しの行の「n pt」と同じ値になる

### Requirement: 作成欄の表示
システムは、PBI の作成欄を、未完了の一覧の区画の末尾（行の表の下）に「+ 作成」の行として表示 SHALL する。作成欄は一覧の行と同じ高さの1行とし、塗りつぶした色のボタンを使わない。一覧が画面より長いときは、スクロールしても作成欄が画面の下端に残る。作成欄に入力して作った PBI は、一覧の末尾、つまり作成欄のすぐ上に追加される。

#### Scenario: スクロールしても作成欄が見える
- **WHEN** ユーザーが PBI の多い一覧を上端から見ている
- **THEN** 作成欄は画面の下端に表示され、そのままタイトルを入力して作成できる

#### Scenario: 作成欄が一覧より目立たない
- **WHEN** ユーザーがバックログ画面を開く
- **THEN** 作成欄は「+ 作成」の行として表示され、塗りつぶした色のボタンではない

#### Scenario: 作った PBI は作成欄の上に並ぶ
- **WHEN** 未完了の一覧に `PBI-1` があるときに、ユーザーが作成欄にタイトルを入力して Enter を押す
- **THEN** 新しい PBI は `PBI-1` の下、作成欄のすぐ上の行に表示される

### Requirement: 詳細パネルの見出し
システムは、詳細パネルの先頭の行に、種類のアイコン付きの PBI の ID と閉じるボタンを表示し、その下に見出しとして読めるタイトルを表示 SHALL する。タイトルは普段は枠の無い 24px の太字として表示し、hover・focus のときだけ入力欄の枠を示して、その場で編集できる。画面上のラベル「タイトル」は表示しないが、読み上げでは「タイトル」の入力欄として識別できる。タイトルのすぐ下にステータスのラベルを置く。その下に「説明」「受入条件」の小見出しとそれぞれの入力欄を置き、最後に「詳細」の小見出しの区画にストーリーポイントを、ラベルを左、値を右に並べた行で表示する。詳細パネルは角丸と枠の箱で包まず、左の 1px の罫線で一覧と区切る。

#### Scenario: 詳細パネルを開く
- **WHEN** ユーザーが PBI-1 の詳細パネルを開く
- **THEN** パネルの先頭の行に「PBI-1」と閉じるボタンが表示され、その下にタイトルが枠の無い見出しの文字として、続けてステータスのラベル、「説明」「受入条件」「詳細」の小見出しが順に表示される

#### Scenario: タイトルをその場で編集する
- **WHEN** ユーザーが詳細パネルのタイトルを押す
- **THEN** タイトルが入力欄の枠付きで編集できる状態になり、変更して保存すると反映される

### Requirement: Done エリア
システムは、選んでいるプロジェクトに `Done` の PBI が1件以上あるとき、未完了の一覧の区画の下に Done エリアを、未完了の一覧と同じ形の区画として表示 SHALL する。Done エリアは折りたたまず、常に開いた状態で表示する。Done エリアの区画の見出しの行には「Done」と、そのプロジェクトの `Done` の PBI の件数とストーリーポイントの合計を表示する。Done エリアの行は未完了の一覧と同じ列（種類のアイコン、ID、タイトル、ステータス、ストーリーポイント、コピー）を持ち、行を選ぶと詳細パネルが開く。Done エリアには作成欄を置かない。`Done` の PBI が1件も無いときは Done エリアを表示しない。

#### Scenario: Done エリアの見出し
- **WHEN** 選んでいるプロジェクトに `Done` で SP 3 と `Done` で SP 未設定の PBI があり、他のプロジェクトに `Done` で SP 5 の PBI がある
- **THEN** 未完了の一覧の区画の下に「Done」の区画が表示され、見出しの行に件数 2 と SP 合計 3 が表示され、2件の PBI がバックログの並び順で並ぶ

#### Scenario: 常に開いている
- **WHEN** ユーザーが `Done` の PBI があるプロジェクトのバックログ画面を開く
- **THEN** Done エリアの PBI の行は、何も操作しなくても表示されている

#### Scenario: Done エリアから詳細を開く
- **WHEN** ユーザーが Done エリアの `PBI-2` のタイトルを押す
- **THEN** `PBI-2` の詳細パネルが開く

#### Scenario: Done の PBI が無いとき
- **WHEN** 選んでいるプロジェクトに `Done` の PBI が1件もない
- **THEN** Done エリアとその見出しは表示されない

### Requirement: 画面の構成
システムは、バックログ画面を Jira のバックログ画面と同じ構成で表示 SHALL する。上から順に、画面の幅いっぱいの上部ナビゲーション（白地に下罫線。左にアプリのアイコンと「Jisaku Jira」、右にエクスポートとインポート）、パンくず「プロジェクト / <選んでいるプロジェクトの名前>」、プロジェクトの名前の見出しと、その右の切り替えのボタンと「…」（プロジェクトの操作）のボタン、ビューのタブ、一覧の区画を置く。ビューのタブには「バックログ」だけを、選択中のタブ（下端にアクセント色の線）として表示し、読み上げでも今のページであることが伝わるようにする。押しても画面は変わらない。読み込み中・接続エラー・共有データが読めないときの画面でも、上部ナビゲーションは表示する。

#### Scenario: バックログ画面を開く
- **WHEN** ユーザーがプロジェクト「Web」を選んだ状態でバックログ画面を開く
- **THEN** 上部ナビゲーションにアプリのアイコンと「Jisaku Jira」、エクスポートとインポートが表示され、その下にパンくず「プロジェクト / Web」、見出し「Web」、選択中の「バックログ」のタブ、一覧の区画がこの順で表示される

#### Scenario: 読み込みエラーの画面
- **WHEN** 共有データに接続できずエラーの画面が表示される
- **THEN** 上部ナビゲーションは表示され、パンくず・見出し・ビューのタブは表示されない

### Requirement: 一覧の区画
システムは、未完了の一覧と Done エリアを、それぞれ薄いグレーの背景と角丸を持つ区画に入れて表示 SHALL する。区画の先頭は見出しの行とし、区画の名前（未完了の一覧は「バックログ」、Done エリアは「Done」）、件数、SP 合計を左に、その区画のステータス別の SP を右に置く。PBI の行の表は、区画の中に白地と 1px の枠で表示する。区画どうしの間は 24px 以上空ける。

#### Scenario: 区画の見出し
- **WHEN** 選んでいるプロジェクトに `To Do` の PBI が2件（SP 3 と 5）、`Done` の PBI が1件（SP 2）ある
- **THEN** 「バックログ」の区画の見出しの行に「2 件の PBI」と「8 pt」、右側に To Do 8・In Progress 0 のバッジが表示され、その下の「Done」の区画の見出しの行に「1 件の PBI」と「2 pt」、右側に Done 2 のバッジが表示される

### Requirement: 一覧の行の表示
システムは、一覧の各行を、並べ替えの持ち手（未完了の一覧だけ）、PBI の種類を示すアイコン、ID、タイトル、ステータス、ストーリーポイント、コピーの順で表示 SHALL する。種類のアイコンは全行で同じ形の小さなアイコンで、読み上げでは読まれない。ストーリーポイントは、数字を灰色の小さなバッジで右揃えに表示し、未設定のときはバッジに「-」を表示して、読み上げでは「未設定」と伝える。`Done` の PBI の行は ID に取り消し線を引く。タイトルが長いときは1行に収めて末尾を省略する。

#### Scenario: SP が未設定の行
- **WHEN** 一覧に SP が未設定の PBI がある
- **THEN** その行の SP の位置に「-」のバッジが表示される

#### Scenario: Done の行の ID
- **WHEN** Done エリアに `PBI-2` がある
- **THEN** Done エリアの `PBI-2` の行の ID「PBI-2」に取り消し線が引かれ、未完了の一覧の行の ID には取り消し線が引かれない

### Requirement: 詳細パネルの保存の操作
システムは、詳細パネルの保存と削除のボタンを、パネルの中をどこまでスクロールしても、パネルの表示範囲の下端に表示 SHALL する。保存と削除の行は白地で、上の 1px の罫線で他の項目と区切り、影は付けない。

#### Scenario: 小さな画面でも保存が見える
- **WHEN** 1280×720 の画面で、説明のある PBI の詳細パネルを開く
- **THEN** パネルをスクロールしなくても「保存」と「削除」のボタンが見える

#### Scenario: スクロールしても保存が見える
- **WHEN** 詳細パネルの中を一番上から一番下までスクロールする
- **THEN** どの位置でも「保存」と「削除」のボタンがパネルの下端に見えている

### Requirement: 狭い画面の一覧の行
システムは、画面の幅が 560px 以下のとき、一覧の各行を2段で表示 SHALL する。1段目にタイトルを、並べ替えの持ち手を除いた行の幅いっぱいに表示し、2段目に ID・ステータス・ストーリーポイント・コピーを並べる。読み上げの順は、幅によらず ID、タイトル、ステータス、ストーリーポイント、コピーの順のまま変えない。一覧の文字は 12px 未満にしない。

#### Scenario: スマホでタイトルが読める
- **WHEN** 390×844 の画面で一覧を開く
- **THEN** 「PBI 一覧の API を作る」が省略されずに1段目に表示され、その下の段に「PBI-1」、ステータス、SP、コピーが並ぶ

#### Scenario: デスクトップは1段のまま
- **WHEN** 1440×900 の画面で一覧を開く
- **THEN** 各行は1段で表示される

### Requirement: 行の右側の項目の並び
システムは、一覧の行のステータス・ストーリーポイント・コピーを互いに 8px 前後の間隔で詰めて並べ、その間隔をステータスの種類によらず一定に表示 SHALL する。1段の行では3つを行の右端に右揃えでまとめ、幅 560px 以下の2段の行では2段目の ID の後ろに左から並べる。

#### Scenario: ステータスと SP の間隔が揃う
- **WHEN** 1440×900 の画面で、「In Progress」の行と「To Do」の行が並んだ一覧を見る
- **THEN** どちらの行も、ステータスのラベルの右端から SP のバッジの左端までの距離が同じになる

#### Scenario: SP とコピーの間を詰める
- **WHEN** 1440×900 の画面で一覧を見る
- **THEN** どの行も、SP のバッジの右端から「コピー」の文字の左端までが 8px 前後になる

#### Scenario: スマホの2段目でも間隔が揃う
- **WHEN** 390×844 の画面で、「In Progress」の行と「To Do」の行が並んだ一覧を見る
- **THEN** どちらの行も、2段目でステータス・SP・コピーが ID の後ろに左から並び、ステータスの右端から SP のバッジの左端までの距離が同じになる
