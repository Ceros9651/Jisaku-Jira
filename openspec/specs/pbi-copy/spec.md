# pbi-copy Specification

## Purpose
PBI を1つの URL で指し示せるようにし、一覧から PBI のリンクと内容をまとめてクリップボードへコピーできるようにする。AI のチャットなどに PBI をそのまま貼って渡すために使う。

## Requirements

### Requirement: PBI のリンク
システムは、各 PBI を `<アプリの URL>#<プロジェクトの id>/PBI-<番号>` の形の URL で指し示せるように SHALL する。`<アプリの URL>` は、いま開いているアプリのページの URL から、クエリ文字列とハッシュを除いたものとする。PBI の番号はプロジェクトごとの連番で、別々のプロジェクトに同じ番号がありうるため、リンクにはその PBI が属するプロジェクトの id を含める。プロジェクトの id はプロジェクトの作成時に決まり、名前を変えても変わらない。このリンクは、どの端末・ブラウザで開いても同じ PBI を指す。このリンクを開くと、共有データを読み込んだあと、リンクのプロジェクトのタブが選ばれ、その PBI の詳細パネルが開いた状態でバックログ画面が表示される。詳細パネルを開いている間、URL のハッシュはこの形になる。

リンクのプロジェクトが無い、またはそのプロジェクトにリンクの番号の PBI が無い場合は、詳細パネルを開かずに、最後に開いていたプロジェクトの一覧だけを表示する。

プロジェクトを含まない以前の形式のリンク `<アプリの URL>#PBI-<番号>` も開ける SHALL。この形式は、最初のタブのプロジェクトの PBI を指すものとして扱い、開くと最初のタブのプロジェクトのその番号の PBI の詳細パネルを開く。最初のタブのプロジェクトにその番号の PBI が無い場合は、詳細パネルを開かずに、最後に開いていたプロジェクトの一覧だけを表示する。

#### Scenario: リンクで PBI を開く
- **WHEN** id が 2 のプロジェクトに `PBI-3` があるバックログで、ユーザーが `https://ceros9651.github.io/Jisaku-Jira/#2/PBI-3` を開く
- **THEN** id が 2 のプロジェクトのタブが選ばれて一覧が表示され、そのプロジェクトの `PBI-3` の詳細パネルが開いている

#### Scenario: 同じ番号の PBI が別のプロジェクトにある
- **WHEN** id が 1 の「Web」と id が 2 の「Tool」の両方に `PBI-3` があり、最後に開いていたプロジェクトが「Web」のときに、ユーザーが `…/Jisaku-Jira/#2/PBI-3` を開く
- **THEN** 「Tool」のタブが選ばれて「Tool」の一覧が表示され、「Tool」の `PBI-3` の詳細パネルが開いている

#### Scenario: 別の端末でリンクを開く
- **WHEN** 端末 A のユーザーが「Tool」の `PBI-3` をコピーし、そのリンクを端末 B のブラウザで開く
- **THEN** 端末 B でも、「Tool」のタブが選ばれ、「Tool」の `PBI-3` の詳細パネルが開いている

#### Scenario: 名前を変えたプロジェクトのリンク
- **WHEN** id が 2 のプロジェクトの名前を「Tool」から「Tools」に変えたあとで、ユーザーが変える前にコピーした `…/Jisaku-Jira/#2/PBI-3` を開く
- **THEN** 「Tools」のタブが選ばれ、`PBI-3` の詳細パネルが開いている

#### Scenario: 別のプロジェクトの PBI のリンク
- **WHEN** 最後に開いていたプロジェクトが「Web」で、id が 2 の「Tool」に `PBI-3` があるときに、ユーザーが `…/Jisaku-Jira/#2/PBI-3` を開く
- **THEN** 「Tool」のタブが選ばれて「Tool」の一覧が表示され、`PBI-3` の詳細パネルが開いている

#### Scenario: 一覧で PBI を選ぶとハッシュが変わる
- **WHEN** ユーザーが id が 2 のプロジェクトの一覧で `PBI-3` を選ぶ
- **THEN** 詳細パネルが開き、URL のハッシュが `#2/PBI-3` になる

#### Scenario: 無い PBI のリンク
- **WHEN** id が 2 のプロジェクトに `PBI-9` が無いバックログで、ユーザーが `…/Jisaku-Jira/#2/PBI-9` を開く
- **THEN** 最後に開いていたプロジェクトの一覧だけが表示され、詳細パネルは開かない

#### Scenario: 無いプロジェクトのリンク
- **WHEN** id が 7 のプロジェクトが無いバックログで、ユーザーが `…/Jisaku-Jira/#7/PBI-1` を開く
- **THEN** 最後に開いていたプロジェクトの一覧だけが表示され、詳細パネルは開かない

#### Scenario: 以前の形式のリンク
- **WHEN** 最初のタブが「Jisaku-Jira-App」で、その中に `PBI-8` があり、最後に開いていたプロジェクトが「Yarikuri」のときに、ユーザーが `…/Jisaku-Jira/#PBI-8` を開く
- **THEN** 「Jisaku-Jira-App」のタブが選ばれ、「Jisaku-Jira-App」の `PBI-8` の詳細パネルが開いている

#### Scenario: 以前の形式のリンクで最初のプロジェクトに無い番号
- **WHEN** 最初のタブのプロジェクトに `PBI-12` が無く、他のプロジェクトに `PBI-12` があるバックログで、ユーザーが `…/Jisaku-Jira/#PBI-12` を開く
- **THEN** 最後に開いていたプロジェクトの一覧だけが表示され、詳細パネルは開かない

### Requirement: 一覧から PBI をコピーする
システムは、一覧の各行の右端に、その PBI をコピーするボタンを表示 SHALL する。ボタンには「コピー」と文字で表示し、読み上げでは「PBI-<番号> をコピー」として識別できるようにする。ボタンを押すと、その PBI のリンクと内容を Markdown にまとめた文字列をクリップボードに書き込む。ボタンを押しても PBI の選択は変わらず、詳細パネルは開かない。

#### Scenario: コピーボタンを押す
- **WHEN** ユーザーが一覧で `PBI-3` の行のコピーボタンを押す
- **THEN** `PBI-3` のリンクと内容の Markdown がクリップボードに入る

#### Scenario: コピーしても詳細パネルは開かない
- **WHEN** 詳細パネルを閉じた状態で、ユーザーが `PBI-3` の行のコピーボタンを押す
- **THEN** 詳細パネルは閉じたままで、URL のハッシュも変わらない

### Requirement: コピーする Markdown の形
コピーする文字列は、次の形の Markdown で SHALL ある。1行目は `## ` に続けて ID とタイトル。空行を挟んで、リンク・カテゴリ・ステータス・ストーリーポイントを箇条書きにする。リンクは、その PBI が属するプロジェクトの id を含む「PBI のリンク」の形とする。カテゴリは画面と同じ表記（タスク / バグ / テスト / セキュリティ）、ステータスは画面と同じ表記（To Do / In Progress / Done）、ストーリーポイントが未設定なら「未設定」とする。続けて `### 説明` の見出しと説明の本文を置き、説明が空なら本文は「（なし）」とする。最後に `### 受入条件` の見出しと受入条件の本文を置き、受入条件が空なら本文は「（なし）」とする。説明と受入条件の本文は、入力された内容の前後の空白を除いてそのまま入れる。

```
## PBI-3 ログイン画面を作る

- リンク: https://ceros9651.github.io/Jisaku-Jira/#1/PBI-3
- カテゴリ: タスク
- ステータス: In Progress
- ストーリーポイント: 5

### 説明

メールアドレスとパスワードでログインできる。

### 受入条件

- 正しいメールアドレスとパスワードでログインできる
- 誤ったパスワードではエラーが表示される
```

#### Scenario: すべての項目がある PBI
- **WHEN** id が 1 のプロジェクトにある、タイトル「ログイン画面を作る」、カテゴリ `タスク`、ステータス `In Progress`、SP 5、説明「メールアドレスとパスワードでログインできる。」、受入条件「- 正しいメールアドレスとパスワードでログインできる\n- 誤ったパスワードではエラーが表示される」の `PBI-3` を、`https://ceros9651.github.io/Jisaku-Jira/` で開いた画面でコピーする
- **THEN** 上の例と同じ文字列がクリップボードに入る

#### Scenario: カテゴリがバグの PBI
- **WHEN** カテゴリ `バグ` の `PBI-4` をコピーする
- **THEN** リンクの行の次に「- カテゴリ: バグ」の行が入る

#### Scenario: SP と説明が空の PBI
- **WHEN** SP が未設定で、説明と受入条件が空の `PBI-1` をコピーする
- **THEN** ストーリーポイントの行は「- ストーリーポイント: 未設定」、説明と受入条件の本文はどちらも「（なし）」になる

#### Scenario: 開いているページの URL がリンクになる
- **WHEN** ユーザーが `http://localhost:5173/Jisaku-Jira/?reload=1#1/PBI-2` を開いた状態で、id が 2 のプロジェクトの `PBI-5` をコピーする
- **THEN** リンクの行は「- リンク: http://localhost:5173/Jisaku-Jira/#2/PBI-5」になる

### Requirement: コピーの結果の表示
コピーに成功したら、システムは押したボタンの文字を「コピー済み」に変えて SHALL 知らせ、約2秒後に「コピー」に戻す。成功と失敗は読み上げでも伝わるようにする。クリップボードに書き込めなかった場合は、ボタンの文字を「コピー失敗」に変えて、同じく約2秒後に戻す。

#### Scenario: コピーに成功する
- **WHEN** ユーザーが `PBI-3` のコピーボタンを押し、クリップボードへの書き込みが成功する
- **THEN** そのボタンの文字が「コピー済み」になり、約2秒後に「コピー」に戻る

#### Scenario: コピーに失敗する
- **WHEN** ユーザーが `PBI-3` のコピーボタンを押し、クリップボードへの書き込みが失敗する
- **THEN** そのボタンの文字が「コピー失敗」になり、バックログの内容は変わらない
