# create-pr-command Specification

## Purpose
チャットでブランチに実装した内容を、`/createPR` の1回の呼び出しで、毎回同じ手順・同じ構成の本文で `dev` への PR にする。コミット・push・PR 作成の前には必ずユーザーの了承を取る。

## Requirements

### Requirement: 呼び出し方
`/createPR` は、ユーザーが明示的に `/createPR` と入力したときだけ動か SHALL なければならない。モデルが会話の流れから自分で呼び出してはならない。引数は任意で、渡された文字列（PBI の番号や本文に足したい注意など）は PR のタイトル・本文を作るときの補足として使う。

#### Scenario: 引数なしで呼ぶ
- **WHEN** ユーザーが `/createPR` とだけ入力する
- **THEN** 今のブランチとチャットの内容から PR を作る手順を始める

#### Scenario: 補足つきで呼ぶ
- **WHEN** ユーザーが `/createPR デプロイ後に全タブの再読み込みが必要` のように入力する
- **THEN** その内容を PR の本文（注意の節など）に反映した案を作る

### Requirement: 作る前の前提の確認
`/createPR` は、コミット・push・PR 作成のどれかを行う前に次を確かめ、満たさないときは何も変えずに理由と次にすべきことを伝えて止め SHALL なければならない。
- 今のブランチが `dev` でも `main` でもない（detached HEAD でもない）
- `gh` が使え、GitHub にログイン済みである
- 最新の `origin/dev` より先のコミットが今のブランチにある（未コミットの変更をコミットする場合は、そのコミットを含めて数える）
- 今のブランチから `dev` への PR がまだ開いていない

#### Scenario: dev ブランチで呼ぶ
- **WHEN** 今のブランチが `dev` のときに `/createPR` を呼ぶ
- **THEN** PR を作らず、作業用のブランチ（例: `PBI-<番号>`）を切ってから呼ぶよう伝えて止まる

#### Scenario: gh にログインしていない
- **WHEN** `gh auth status` が未ログインを返す
- **THEN** PR を作らず、`gh auth login` を実行するよう伝えて止まる

#### Scenario: dev との差が無い
- **WHEN** 今のブランチに `origin/dev` より先のコミットが無く、未コミットの変更も無い
- **THEN** PR にする変更が無いと伝えて止まる

#### Scenario: すでに PR が開いている
- **WHEN** 今のブランチから `dev` への PR がすでに開いている
- **THEN** 新しい PR は作らず、その PR の URL を伝える。push していないコミットがあれば、push してよいかをユーザーに確かめ、了承されたときだけ push する

### Requirement: 未コミットの変更のコミット
今のブランチに未コミットの変更（ステージ済み・未ステージ・追跡していないファイル）があるとき、`/createPR` は変更されたファイルの一覧とコミットメッセージの案をユーザーに見せ、了承されてからコミット SHALL しなければならない。了承されなければコミットせず、PR も作らずに止まる。コミットメッセージはリポジトリの慣例（`feat:` / `fix:` / `docs:` / `chore:` などの接頭辞と日本語の要約）に合わせる。`.env` などの秘密情報を含みうるファイルが一覧にあれば、コミットに含めずにユーザーへ知らせる。

#### Scenario: 未コミットの変更を了承してコミットする
- **WHEN** 未コミットの変更がある状態で `/createPR` を呼び、ユーザーがファイルの一覧とメッセージの案を了承する
- **THEN** その内容でコミットしてから、PR のタイトルと本文の案づくりに進む

#### Scenario: コミットを断る
- **WHEN** ユーザーがコミットの案を了承しない
- **THEN** コミットせず、push も PR の作成もせずに止まる

#### Scenario: 秘密情報らしいファイルがある
- **WHEN** 未コミットの変更に `.env` や `.env.local` のようなファイルが含まれる
- **THEN** そのファイルをコミットの対象から外し、外したことをユーザーに伝える

### Requirement: PR のタイトルと本文
`/createPR` は、PR のタイトルと本文を、このチャットで実装した内容・`origin/dev` からのコミットと差分・関係する OpenSpec の change から作ら SHALL なければならない。
- タイトルは、ブランチ名が `PBI-<番号>` で始まるときは `PBI-<番号> <変更の要約>` とし、それ以外は変更の要約だけとする。
- 本文は日本語で、「## 概要」「## 変更」「## 確認」の節をこの順に持つ。必要なときだけ注意やマージ後の作業の節を足す。最後に `🤖 Generated with [Claude Code](https://claude.com/claude-code)` を置く。
- 「## 概要」には、PBI の番号が分かるときは PBI の番号と公開 URL のリンク（`https://ceros9651.github.io/Jisaku-Jira/#PBI-<番号>`）を含める。
- 「## 確認」には、このチャットで実際に実行・確認したことだけを書く。実行していないテストやビルドを通ったと書いてはならない。何も確認していないときは、確認していないことをそのまま書く。

#### Scenario: PBI のブランチの PR
- **WHEN** ブランチ `PBI-6` で `/createPR` を呼ぶ
- **THEN** タイトルが `PBI-6 ` で始まり、概要に `https://ceros9651.github.io/Jisaku-Jira/#PBI-6` が含まれる案になる

#### Scenario: チャットでテストを通した
- **WHEN** このチャットで `npm test` と `npm run build` を実行して通っている
- **THEN** 「## 確認」に、その 2 つが通ったことが書かれる

#### Scenario: チャットで何も確認していない
- **WHEN** このチャットでテスト・型チェック・ビルド・画面の確認のどれも行っていない
- **THEN** 「## 確認」に通ったとは書かず、確認していないことが分かる書き方になる。あわせて、PR を作る前に `npm run typecheck && npm test && npm run build` を実行するかをユーザーに尋ねる

### Requirement: 作る前の了承
`/createPR` は、push と PR の作成を行う前に、ベースブランチ（`dev`）・ヘッドブランチ・タイトル・本文の全文をユーザーに見せ、了承を得 SHALL なければならない。ユーザーは「作成する」「直してほしい点を伝える」「やめる」を選べる。直す点が伝えられたら案を直して再び了承を求め、「やめる」が選ばれたら push も PR の作成もせずに止まる。

#### Scenario: 了承して作成する
- **WHEN** ユーザーがタイトルと本文の案を見て「作成する」を選ぶ
- **THEN** 今のブランチを `origin` に push し、`dev` をベースにした PR を作り、PR の URL を伝える

#### Scenario: 直してから作成する
- **WHEN** ユーザーが本文の直してほしい点を伝える
- **THEN** 案を直して再び全文を見せ、了承を求める

#### Scenario: やめる
- **WHEN** ユーザーが「やめる」を選ぶ
- **THEN** push も PR の作成もせずに止まる（それまでにしたコミットは残る）

### Requirement: してはならない操作
`/createPR` は、PR のベースを `dev` 以外にしてはならず、force push・PR のマージ・コミットフックや署名の省略（`--no-verify` など）・他のブランチへの push を行ってはなら SHALL ない。push やPR の作成に失敗したときは、エラーの内容をそのまま伝えて止まり、別の方法で回避しない。

#### Scenario: push が拒否される
- **WHEN** リモートのブランチが先に進んでいて push が拒否される
- **THEN** force push はせず、拒否されたことと原因（リモートに手元に無いコミットがある）を伝えて止まる

#### Scenario: PR の作成
- **WHEN** PR を作る
- **THEN** ベースは常に `dev` で、PR はマージされずに開いた状態で残る
