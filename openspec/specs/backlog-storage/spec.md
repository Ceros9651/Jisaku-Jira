# backlog-storage Specification

## Purpose
バックログのデータをすべての端末で共有する1つの保存先に置き、どの端末で開いても同じ内容を表示する。ファイルへの書き出しと読み込みでバックアップと復元をでき、以前の版がブラウザに残したデータを共有データへ移せるようにする。

## Requirements

### Requirement: 共有データへの自動保存
システムは、PBI の作成・編集・削除・並べ替えと、プロジェクトの作成・名前変更・削除のたびに、すべてのプロジェクト（プロジェクトの名前と順序、各プロジェクトの PBI と並び順）と次に発行する ID 番号を、すべての端末から読み書きする1つの共有データへ保存 SHALL する。どの端末・ブラウザでアプリを開いても、共有データの同じ内容が表示される。共有データは、アプリの URL を知っている人なら誰でもサインインせずに読み書きできる。共有データの保存先は、アプリが使う1件のデータ以外への読み書きを拒否する。

#### Scenario: 別の端末で開いても同じ内容
- **WHEN** 端末 A のユーザーが PBI を2件作成し、そのあと端末 B のブラウザでアプリを開く
- **THEN** 端末 B に、作成した2件の PBI が同じ ID・内容・順序で表示される

#### Scenario: 再読み込み後もデータが残る
- **WHEN** ユーザーが PBI を2件作成してページを再読み込みする
- **THEN** 作成した2件の PBI が同じ ID・内容・順序で表示される

#### Scenario: 再読み込み後も採番が続く
- **WHEN** `PBI-1`〜`PBI-3` を作成して `PBI-3` を削除し、ページを再読み込みしてから PBI を作成する
- **THEN** 新しい PBI の ID は `PBI-4` になる

#### Scenario: 別の端末でもプロジェクトが同じ
- **WHEN** 端末 A のユーザーがプロジェクト「Tool」を作成して PBI を1件追加し、そのあと端末 B でアプリを開く
- **THEN** 端末 B に「Tool」のタブがあり、その中に追加した PBI が表示される

#### Scenario: 共有データがまだ無い
- **WHEN** 共有データが一度も保存されていない状態でアプリを開く
- **THEN** PBI の無い「マイプロジェクト」1つのバックログが表示され、最初の操作で共有データが作られる

### Requirement: 保存失敗時の通知
共有データへの保存に失敗した場合（接続できない、保存先に拒否されたなど）、システムは変更を保存できなかったことをユーザーに表示 SHALL する。保存できなかった操作の結果は画面から取り消し、共有データの内容を表示する。

#### Scenario: 保存できない
- **WHEN** ユーザーが PBI を作成したが、共有データへの書き込みが失敗する
- **THEN** 変更を保存できなかったことが表示され、作成した PBI は一覧から消える

### Requirement: 保存データが読めないときの扱い
起動時、または他の端末での変更を受け取ったときに、共有データが壊れている、または形式が合わない場合、システムはその共有データを上書き SHALL しない。読み込めなかったことと理由をユーザーに表示し、空のバックログで始めるか、インポートするかを選べるようにする。空のバックログで始めることを選んだ場合は、確認を経て共有データを空のバックログで上書きする。

#### Scenario: 壊れた保存データ
- **WHEN** 共有データが JSON として読めない状態でアプリを開く
- **THEN** 読み込めなかったことが表示され、ユーザーが選ぶまで共有データは上書きされない

### Requirement: JSON エクスポート
システムは、共有データのすべてのプロジェクトを1つの JSON ファイルとしてダウンロードできる機能を提供 SHALL する。ファイルにはプロジェクトの名前と順序、各プロジェクトの PBI のすべての項目と並び順、次に発行する ID 番号、データ形式のバージョンを含める。

#### Scenario: エクスポートする
- **WHEN** プロジェクト「Web」と「Tool」がある状態で、ユーザーがエクスポートを選ぶ
- **THEN** 「Web」と「Tool」の両方とその PBI を含む JSON ファイルがダウンロードされる

### Requirement: JSON インポート
システムは、エクスポートした JSON ファイルを読み込み、確認を経たうえで共有データのすべてのプロジェクトを置き換える機能を提供 SHALL する。置き換えは、共有データを使うすべての端末に反映される。確認では、置き換えられる現在のプロジェクト数と PBI の件数、ファイルに含まれるプロジェクト数と PBI の件数を示し、他の人の画面の内容も置き換わることを示す。インポート後の採番は、ファイルに含まれる次の ID 番号から続ける。インポート後は、ファイルの最初のプロジェクトを選んだ状態にする。形式が不正なファイルは読み込まず、共有データを変更しない。

#### Scenario: 正しいファイルをインポートする
- **WHEN** ユーザーが、プロジェクト「Web」に `PBI-1`、「Tool」に `PBI-5` を含み次の番号が 6 のファイルを選び、置き換えを確認する
- **THEN** プロジェクトが「Web」と「Tool」に置き換わって「Web」が選ばれ、次に作成する PBI の ID は `PBI-6` になる

#### Scenario: インポートが他の端末に反映される
- **WHEN** 端末 A のユーザーがファイルをインポートして置き換えを確認する
- **THEN** 端末 B の画面も、ファイルの内容に置き換わる

#### Scenario: 確認で取り消す
- **WHEN** ユーザーがファイルを選んだあと、置き換えの確認で取り消す
- **THEN** 共有データのプロジェクトと PBI は変更されない

#### Scenario: 不正なファイル
- **WHEN** ユーザーが JSON として読めないファイル、必要な項目が欠けたファイル、またはプロジェクトが1つも無いファイルを選ぶ
- **THEN** 読み込めない理由が表示され、共有データは変更されない

#### Scenario: PBI の番号が重複したファイル
- **WHEN** ユーザーが、別々のプロジェクトに同じ番号の PBI を含むファイルを選ぶ
- **THEN** 番号が重複していることが表示され、共有データは変更されない

### Requirement: 旧形式のデータの読み込み
システムは、プロジェクトの無い旧形式（version 1）のエクスポートファイルと、このブラウザに残った version 1 の以前のデータを読み込める SHALL。読み込むと、すべての PBI を元の並び順のまま1つのプロジェクト「マイプロジェクト」に入れ、PBI の ID と内容、次に発行する ID 番号は変えない。

#### Scenario: 旧形式の保存データで開く
- **WHEN** このブラウザのローカルストレージに `PBI-1`, `PBI-2` を含む旧形式の以前のデータがある状態でページを開く
- **THEN** 以前のデータが残っていることと「1 プロジェクト・2 件」が表示され、共有データは変わらない

#### Scenario: 旧形式のファイルをインポートする
- **WHEN** ユーザーが以前エクスポートした旧形式のファイルを選び、置き換えを確認する
- **THEN** 共有データのすべてのプロジェクトが、ファイルの PBI を持つ「マイプロジェクト」1つに置き換わる

### Requirement: このブラウザに残った以前のデータの取り込み
システムは、起動時にこのブラウザのローカルストレージに以前の版で保存したバックログ（version 1 の形式を含む）が残っていて読み込める場合、そのことと内容のプロジェクト数・PBI の件数を表示 SHALL する。ユーザーは次のいずれかを選べる。共有データへの取り込みは、インポートと同じ確認（現在の共有データと以前のデータの、それぞれのプロジェクト数と件数を示す）を経て、共有データ全体を以前のデータで置き換える。取り込みが保存できたら、このブラウザの以前のデータを消し、表示も消す。ファイルへの書き出しは、以前のデータをエクスポートと同じ形式のファイルとしてダウンロードする。このブラウザからの削除は、確認を経て以前のデータを消し、共有データは変えない。システムは以前のデータを自動では取り込まない。

#### Scenario: 以前のデータがあることを表示する
- **WHEN** このブラウザのローカルストレージに、2 プロジェクト・5 件の以前のデータがある状態でアプリを開く
- **THEN** 以前のデータが残っていることと「2 プロジェクト・5 件」が表示され、共有データは変わらない

#### Scenario: 以前のデータを取り込む
- **WHEN** ユーザーが以前のデータの取り込みを選び、置き換えを確認する
- **THEN** 共有データが以前のデータの内容に置き換わり、このブラウザの以前のデータと、その表示が消える

#### Scenario: 以前のデータを書き出す
- **WHEN** ユーザーが以前のデータのファイルへの書き出しを選ぶ
- **THEN** 以前のデータを含む JSON ファイルがダウンロードされ、以前のデータと共有データは変わらない

#### Scenario: 以前のデータを消す
- **WHEN** ユーザーが以前のデータの削除を選び、確認で削除を選ぶ
- **THEN** このブラウザの以前のデータとその表示が消え、共有データは変わらない

#### Scenario: version 1 の以前のデータ
- **WHEN** ローカルストレージに `PBI-1`, `PBI-2` を含み次の番号が 4 の version 1 の以前のデータがある状態で、ユーザーがそれを取り込む
- **THEN** 共有データは「マイプロジェクト」1つに `PBI-1`, `PBI-2` が同じ順序で入った内容になり、次に作成する PBI の ID は `PBI-4` になる

### Requirement: 受入条件を持たないデータの読み込み
システムは、受入条件の項目を持たない PBI を含む共有データ、エクスポートファイル、このブラウザに残った以前のデータ（version 1 を含む）を、読み込めないデータとして SHALL 扱わない。受入条件の項目が無い PBI は、受入条件が空の PBI として読み込み、他の項目と並び順、次に発行する ID 番号は変えない。受入条件の項目があって文字列でない PBI を含むデータは、形式が不正なデータとして扱う。

#### Scenario: 受入条件の無い共有データで開く
- **WHEN** 受入条件の項目が無い `PBI-1`, `PBI-2` を含む共有データがある状態でアプリを開く
- **THEN** `PBI-1`, `PBI-2` が同じ内容と順序で表示され、どちらの受入条件も空になる

#### Scenario: 受入条件の無いファイルをインポートする
- **WHEN** ユーザーが、この変更より前にエクスポートしたファイルを選び、置き換えを確認する
- **THEN** ファイルの PBI がすべて読み込まれ、受入条件はすべて空になる

#### Scenario: 受入条件が文字列でないファイル
- **WHEN** ユーザーが、受入条件に数値が入った PBI を含むファイルを選ぶ
- **THEN** 受入条件が不正であることが表示され、共有データは変更されない

#### Scenario: エクスポートに受入条件が含まれる
- **WHEN** 受入条件を書いた PBI がある状態でエクスポートし、そのファイルをインポートする
- **THEN** インポート後の PBI の受入条件は、エクスポートしたときと同じになる
