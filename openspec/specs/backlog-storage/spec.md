# backlog-storage Specification

## Purpose
サーバーを持たない静的サイトとして、バックログのデータをブラウザ内に保存し、ファイルへの書き出しと読み込みでバックアップや端末間の移行をできるようにする。

## Requirements

### Requirement: ブラウザへの自動保存
システムは、PBI の作成・編集・削除・並べ替えのたびに、バックログ全体（PBI、並び順、次に発行する ID 番号）をブラウザのローカルストレージへ保存 SHALL する。ページを再読み込みしたり、同じブラウザで開き直したりしても、保存した内容が表示される。

#### Scenario: 再読み込み後もデータが残る
- **WHEN** ユーザーが PBI を2件作成してページを再読み込みする
- **THEN** 作成した2件の PBI が同じ ID・内容・順序で表示される

#### Scenario: 再読み込み後も採番が続く
- **WHEN** `PBI-1`〜`PBI-3` を作成して `PBI-3` を削除し、ページを再読み込みしてから PBI を作成する
- **THEN** 新しい PBI の ID は `PBI-4` になる

### Requirement: 保存失敗時の通知
ブラウザへの保存に失敗した場合（ストレージが使えない、容量超過など）、システムは保存できなかったことをユーザーに表示 SHALL する。画面上の内容はそのまま残し、エクスポートできる状態を保つ。

#### Scenario: 保存できない
- **WHEN** ローカルストレージへの書き込みが失敗する
- **THEN** 保存できなかったことと、エクスポートでデータを退避できることが表示される

### Requirement: 保存データが読めないときの扱い
起動時に保存データが壊れている、または形式が合わない場合、システムはその保存データを上書き SHALL しない。読み込めなかったことをユーザーに表示し、空のバックログで操作を始めるか、インポートするかを選べるようにする。

#### Scenario: 壊れた保存データ
- **WHEN** ローカルストレージの保存データが JSON として読めない状態でページを開く
- **THEN** 読み込めなかったことが表示され、ユーザーが選ぶまで元の保存データは上書きされない

### Requirement: JSON エクスポート
システムは、バックログ全体を1つの JSON ファイルとしてダウンロードできる機能を提供 SHALL する。ファイルには PBI のすべての項目、並び順、次に発行する ID 番号、データ形式のバージョンを含める。

#### Scenario: エクスポートする
- **WHEN** ユーザーがエクスポートを選ぶ
- **THEN** バックログ全体を含む JSON ファイルがダウンロードされる

### Requirement: JSON インポート
システムは、エクスポートした JSON ファイルを読み込み、確認を経たうえで現在のバックログ全体を置き換える機能を提供 SHALL する。インポート後の採番は、ファイルに含まれる次の ID 番号から続ける。形式が不正なファイルは読み込まず、現在のバックログを変更しない。

#### Scenario: 正しいファイルをインポートする
- **WHEN** ユーザーが `PBI-1`, `PBI-5` を含み次の番号が 6 のファイルを選び、置き換えを確認する
- **THEN** バックログがファイルの内容と順序に置き換わり、次に作成する PBI の ID は `PBI-6` になる

#### Scenario: 確認で取り消す
- **WHEN** ユーザーがファイルを選んだあと、置き換えの確認で取り消す
- **THEN** 現在のバックログは変更されない

#### Scenario: 不正なファイル
- **WHEN** ユーザーが JSON として読めないファイル、または必要な項目が欠けたファイルを選ぶ
- **THEN** 読み込めない理由が表示され、現在のバックログは変更されない
