# backlog-storage Specification

## Purpose
サーバーを持たない静的サイトとして、バックログのデータをブラウザ内に保存し、ファイルへの書き出しと読み込みでバックアップや端末間の移行をできるようにする。

## Requirements

### Requirement: ブラウザへの自動保存
システムは、PBI の作成・編集・削除・並べ替えと、プロジェクトの作成・名前変更・削除のたびに、すべてのプロジェクト（プロジェクトの名前と順序、各プロジェクトの PBI と並び順）と次に発行する ID 番号をブラウザのローカルストレージへ保存 SHALL する。ページを再読み込みしたり、同じブラウザで開き直したりしても、保存した内容が表示される。

#### Scenario: 再読み込み後もデータが残る
- **WHEN** ユーザーが PBI を2件作成してページを再読み込みする
- **THEN** 作成した2件の PBI が同じ ID・内容・順序で表示される

#### Scenario: 再読み込み後も採番が続く
- **WHEN** `PBI-1`〜`PBI-3` を作成して `PBI-3` を削除し、ページを再読み込みしてから PBI を作成する
- **THEN** 新しい PBI の ID は `PBI-4` になる

#### Scenario: 再読み込み後もプロジェクトが残る
- **WHEN** ユーザーがプロジェクト「Tool」を作成して PBI を1件追加し、ページを再読み込みする
- **THEN** 「Tool」のタブがあり、その中に追加した PBI が表示される

### Requirement: 保存失敗時の通知
ブラウザへの保存に失敗した場合（ストレージが使えない、容量超過など）、システムは保存できなかったことをユーザーに表示 SHALL する。画面上の内容はそのまま残し、エクスポートできる状態を保つ。

#### Scenario: 保存できない
- **WHEN** ローカルストレージへの書き込みが失敗する
- **THEN** 保存できなかったことと、エクスポートでデータを退避できることが表示される

### Requirement: 保存データが読めないときの扱い
起動時に保存データが壊れている、または形式が合わない場合、システムはその保存データを上書き SHALL しない。読み込めなかったことをユーザーに表示し、空のバックログで操作を始めるか、インポートするかを選べるようにする。

#### Scenario: 壊れた保存データ
- **WHEN** ローカルストレージの保存データが JSON として読めない状態でページを開く
- **THEN** 読み込めなかったことが表示され、ユーザーが選ぶまで元の保存データは上書きされない

### Requirement: JSON エクスポート
システムは、すべてのプロジェクトを1つの JSON ファイルとしてダウンロードできる機能を提供 SHALL する。ファイルにはプロジェクトの名前と順序、各プロジェクトの PBI のすべての項目と並び順、次に発行する ID 番号、データ形式のバージョンを含める。

#### Scenario: エクスポートする
- **WHEN** プロジェクト「Web」と「Tool」がある状態で、ユーザーがエクスポートを選ぶ
- **THEN** 「Web」と「Tool」の両方とその PBI を含む JSON ファイルがダウンロードされる

### Requirement: JSON インポート
システムは、エクスポートした JSON ファイルを読み込み、確認を経たうえで現在のすべてのプロジェクトを置き換える機能を提供 SHALL する。確認では、置き換えられる現在のプロジェクト数と PBI の件数、ファイルに含まれるプロジェクト数と PBI の件数を示す。インポート後の採番は、ファイルに含まれる次の ID 番号から続ける。インポート後は、ファイルの最初のプロジェクトを選んだ状態にする。形式が不正なファイルは読み込まず、現在のデータを変更しない。

#### Scenario: 正しいファイルをインポートする
- **WHEN** ユーザーが、プロジェクト「Web」に `PBI-1`、「Tool」に `PBI-5` を含み次の番号が 6 のファイルを選び、置き換えを確認する
- **THEN** プロジェクトが「Web」と「Tool」に置き換わって「Web」が選ばれ、次に作成する PBI の ID は `PBI-6` になる

#### Scenario: 確認で取り消す
- **WHEN** ユーザーがファイルを選んだあと、置き換えの確認で取り消す
- **THEN** 現在のプロジェクトと PBI は変更されない

#### Scenario: 不正なファイル
- **WHEN** ユーザーが JSON として読めないファイル、必要な項目が欠けたファイル、またはプロジェクトが1つも無いファイルを選ぶ
- **THEN** 読み込めない理由が表示され、現在のデータは変更されない

#### Scenario: PBI の番号が重複したファイル
- **WHEN** ユーザーが、別々のプロジェクトに同じ番号の PBI を含むファイルを選ぶ
- **THEN** 番号が重複していることが表示され、現在のデータは変更されない

### Requirement: 旧形式のデータの読み込み
システムは、プロジェクトの無い旧形式（version 1）の保存データとエクスポートファイルを読み込める SHALL。読み込むと、すべての PBI を元の並び順のまま1つのプロジェクト「マイプロジェクト」に入れ、PBI の ID と内容、次に発行する ID 番号は変えない。旧形式の保存データは、次の保存で新しい形式に書き直す。

#### Scenario: 旧形式の保存データで開く
- **WHEN** ローカルストレージに `PBI-1`, `PBI-2` を含み次の番号が 4 の旧形式の保存データがある状態でページを開く
- **THEN** 「マイプロジェクト」のタブだけがあり、その一覧に `PBI-1`, `PBI-2` が同じ順序で表示され、次に作成する PBI の ID は `PBI-4` になる

#### Scenario: 旧形式のファイルをインポートする
- **WHEN** ユーザーが以前エクスポートした旧形式のファイルを選び、置き換えを確認する
- **THEN** すべてのプロジェクトが、ファイルの PBI を持つ「マイプロジェクト」1つに置き換わる
