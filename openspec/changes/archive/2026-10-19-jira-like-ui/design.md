# Design

## Context

画面は `src/App.tsx` が1枚で組み立てている。今の構成は、上から灰色のヘッダー（アプリ名とエクスポート・インポート）、文字だけのプロジェクトのタブの帯（`ProjectTabs`）、警告帯、そして `main` の2列グリッド（左に見出しの行・作成欄・表・Done エリア、右に角丸の枠で包んだ sticky の詳細パネル）。色は暖色寄りの無彩色（`--gray-*`）とアクセントの青1色で、`docs/design-principles.md` が「飾りアイコン禁止」「角丸の箱は詳細パネル・ダイアログ・警告帯だけ」「文字サイズは 12/13/14/18px の4段階」「プロジェクトの切り替えは文字だけのタブ」などを決めている。

ユーザーが示した本家 Jira のバックログ画面との主な違いは次のとおり。

| | 本家 Jira | 今のアプリ |
|---|---|---|
| 最上部 | 白地の上部ナビ（ロゴ・検索・作成） | 灰色のヘッダー |
| 見出し | パンくず＋24px の見出し＋右に操作 | 18px の見出しと集計が1行 |
| ビュー | 要約・バックログ…のタブ | 無し（代わりにプロジェクトのタブ） |
| 一覧 | 薄いグレーの角丸の区画。見出しの行に件数とステータス別 SP | 区画無し、罫線の表 |
| 行 | 種類アイコン・キー・要約…ステータス・SP バッジ | 持ち手・ID・タイトル・ステータス・SP の数字 |
| ステータス | 大文字にしないボタン状、矢印は常時 | 大文字の Lozenge、矢印は hover 時 |
| 作成 | 区画の末尾の「+ 作成」 | 一覧の上の sticky の行 |
| 詳細 | 右端に貼り付いた全高のパネル、24px のタイトル、小見出しの区画 | 角丸の枠の箱、18px のタイトル |

ユーザーとの確認で、範囲は「見た目だけ」（データ・保存・同期・リンクは変えない）、原則と衝突する Jira の要素は design-principles.md に例外として追記して採り入れる、プロジェクトの切り替えはパンくず＋見出しに統合する、と決めた。

## Goals / Non-Goals

**Goals:**

- Jira を使っている人が、一目で Jira のバックログ画面だと分かる骨格（上部ナビ・パンくず・見出し・ビューのタブ・区画・右端の詳細パネル）にする
- 一覧の行・ステータス・SP・詳細パネルの部品の見た目を Jira に合わせる
- 今ある操作（作成・編集・ステータス変更・並べ替え・コピー・削除・プロジェクトの作成/名前変更/削除・エクスポート/インポート）は、置き場所が変わってもすべて残し、キーボードと読み上げでも使えるままにする
- 衝突する原則を、範囲を限った例外として design-principles.md に残す

**Non-Goals:**

- スプリント、担当者、ラベル、優先度、エピック、検索、フィルター、サブタスク、課題の種類の区別など、データに無い機能（スクショには写っているが作らない）
- 上部ナビの検索欄、「作成」ボタン、通知・ヘルプ・設定・アバター、左のサイドバー、「要約」「タイムライン」などバックログ以外のビュー（偽の操作になるため置かない）
- Atlassian Sans の使用。公式の配布は Atlassian 社内向けに限られ、デザイン素材のライセンスも Atlassian 製品と連携するソフトウェアに用途が限られているため、連携しないこのアプリでは使えない。近い見た目の Inter で代える（10. を参照）
- ダークモード

## Decisions

### 1. レイアウトはウィンドウのスクロールのまま、詳細パネルだけ sticky の全高にする

`App` を「sticky の上部ナビ（48px）」＋「本体」にする。本体はパネルを開いたとき `grid-template-columns: minmax(0, 1fr) minmax(360px, 440px)` の2列で、左の列にだけ左右 24px の余白を付け、右の列（詳細パネル）は余白無しで画面の右端に接する。詳細パネルは `position: sticky; top: 48px; height: calc(100vh - 48px); overflow-y: auto; border-left: 1px solid` にする。

- 代替案: 本体全体を `height: 100vh` の固定にして左右を別々のスクロール領域にする（Jira の実装に近い）。却下。作成欄の sticky（下端）、ドラッグ中の自動スクロール、既存のテストやスクリーンショット確認がウィンドウのスクロールを前提にしており、変える量に見合わない。sticky で見た目は同じになる。
- 760px 以下では今と同じく1列にし、パネルは一覧の下に `position: static`・高さ自動で置く。

### 2. プロジェクトの切り替えは、自作の「メニューボタン」部品で作る

WAI-ARIA の Menu Button パターンで、共通の小さな `Menu` 部品（`src/components/Menu.tsx`）を作り、2か所で使う。

- 切り替えのボタン（`aria-label="プロジェクトを切り替え"`、見出しの右の下向き矢印）: 項目は `role="menuitemradio"`＋`aria-checked` のプロジェクト名（作成順）、区切り線、`role="menuitem"` の「プロジェクトを追加」
- 「…」ボタン（`aria-label="プロジェクトの操作"`）: 「名前を変更」「削除」。削除はプロジェクトが1つのとき `aria-disabled="true"` にし、項目の下に「プロジェクトが1つだけのときは削除できません」を小さく出す

`Menu` は、開くと最初の項目（切り替えでは選択中の項目）にフォーカスし、上下の矢印・Home/End で移動、Enter/Space で実行、Escape と外側のクリックで閉じてボタンにフォーカスを戻す。位置はボタンの下に `position: absolute` で出し、`max-width: min(320px, 100vw - 32px)`、長い名前は折り返す。影は上に重なるものなので `--shadow-overlay` を付ける。

- 代替案: ネイティブの `<select>`。却下。「プロジェクトを追加」のような操作を項目に混ぜられず、見た目も Jira の項目メニューにならない。
- 代替案: Popover API（`popover` 属性）。今の jsdom で振る舞いを試験しにくいため、今回は使わない。
- 依存ライブラリは足さない。2か所だけなので自作で足りる。

プロジェクト名の入力は、今の `ProjectNameForm`（`size="heading"`）を見出しの位置で再利用する。`App` の状態を `renaming: boolean` から `nameEdit: 'rename' | 'create' | null` に広げ、'create' のときは空の入力欄を見出しの位置に出す。`ProjectTabs` とそのタブ用の CSS は削除する。

### 3. パンくずとビューのタブは、操作にしない

- パンくずは `<nav aria-label="パンくず"><ol>` で「プロジェクト」と「<名前>」（`aria-current="page"`）を並べる。「プロジェクト」の先に一覧画面は無いのでリンクにしない。
- ビューのタブは `<nav aria-label="ビュー">` の中に「バックログ」1つを `aria-current="page"` の文字で置き、下端 2px のアクセント色の線で選択中に見せる。`<a href="#">` にするとハッシュ（開いている PBI）を消してしまうため、リンクにしない。

### 4. 区画と行

- 区画（`.section`）は `background: var(--surface-sunken)`、角丸 `--radius-section`（8px）、内側の余白 8px/12px。見出しの行は区画名（14px 太字）、「n 件の PBI」、「n pt」、右端にステータス別 SP のバッジ。今の `data-testid="backlog-summary"` と `done-summary` は区画の見出しの行に移して残す（テストの手がかり）。
- 行の表は区画の中で `background: var(--surface); border: 1px solid var(--border); border-radius: var(--radius-control)`。行の区切りは今どおり 1px の罫線。
- 列は「持ち手 28px・種類アイコン 24px・ID・タイトル・ステータス・SP・コピー」。SP は `.pointsBadge`（灰色の背景、角丸 4px、12px、最小幅 24px、中央揃え）。未設定は「-」を `aria-hidden` で出し、読み上げ用に `visually-hidden` の「未設定」を添える。
- Done の行は `BacklogTable` に渡る `pbi.status === 'done'` で ID のセルに `text-decoration: line-through` を付ける（表ごとの指定ではなく行の状態で決め、Done エリア以外に出ることは無い）。

### 5. 作成欄は区画の末尾で sticky bottom

`CreatePbiForm` を未完了の区画の表の直後に置き、`position: sticky; bottom: 0` にする。見た目は「+」の線画と「作成」のプレースホルダーの1行（高さ 38px、白地、上に 1px の罫線）。Enter で作成し、今の「作成」の枠線ボタンは残す（マウスでも確定できるように）が、入力欄にフォーカスがあるときだけ出す。空の一覧・未完了が無いときも、区画の中に空の文と作成欄を出す。

- 代替案: Jira のように「+ 作成」の文字ボタンを押してから入力欄に変える。却下。今は入力欄がいつも出ていて1手で作れる。手数を増やさない。

### 6. ステータスのラベル

`StatusSelect.module.css` で `text-transform: uppercase` と `letter-spacing` をやめ、矢印の `background-image` を常に付ける。高さ 24px、文字 12px/600、左右の余白を広げてボタンらしく見せる。色の3種と `--status-*` の名前は変えず、値だけを 1. のトークンに合わせて調整し、文字と背景のコントラスト比 4.5:1 以上を保つ。

### 7. トークンは名前を変えずに値を寄せる

`src/styles/tokens.css` の変数名はそのままにして、全部品の書き換えを避ける。値は Atlassian のデザイントークンに近い寒色寄りに変える（目安）。

| 変数 | 今 | 新 |
|---|---|---|
| `--gray-900`（本文） | #1e1e1c | #292a2e |
| `--gray-700` | #4a4a46 | #505258 |
| `--gray-500`（muted） | #82827d | #6b6e76 |
| `--gray-300` | #c9c9c5 | #b7b9be |
| `--gray-200`（罫線） | #e1e1de | #dddee1 |
| `--gray-100` | #efefed | #ebecf0 |
| `--gray-50`（区画・沈んだ面） | #f7f7f6 | #f8f8f8 |
| `--accent` | #1f5fbf | #1868db |
| `--accent-hover` | #194f9f | #1558bc |
| `--accent-subtle`（選択中の行） | #e9f0fb | #e9f2fe |

追加は `--text-xl: 24px`（画面の見出しと詳細パネルのタイトル）と `--radius-section: 8px`（一覧の区画）。本文の既定は今の 14px のまま。muted の文字は白地と区画の灰色の両方で 4.5:1 以上になることを確かめる。

### 8. アイコンは1つのファイルに線画で置く

`src/components/icons.tsx` に、`aria-hidden` の inline SVG として「PBI の種類（青い角丸の四角に白いチェック、16px）」「下向き矢印」「横三点（…）」「閉じる（今の × を移す）」「+」を置く。並べ替えの持ち手は今の SVG のまま。アプリのアイコンは `public/icon.svg` を上部ナビで 24px に表示する。アイコンを置いたボタンには必ず `aria-label` を付ける。

### 9. design-principles.md の改訂

「例外」の節に、この change の名前（jira-like-ui）付きで次を追記する。

- 機能を持つ・Jira の文脈で意味を持つアイコンに限り使う：PBI の種類、メニューを開く矢印、「…」、閉じる、作成の「+」
- 一覧の区画（未完了・Done）は薄いグレーの 8px 角丸で包み、行の表は区画の中で 1px の枠と 4px 角丸の白地にする
- 上部ナビ・パンくず・ビューのタブを置く。プロジェクトの切り替えは見出しの横のメニュー
- 文字サイズに 24px（画面の見出し・詳細パネルのタイトル）を加える
- 欧文・数字の書体を Inter にする（和文はシステムフォント）。Web フォントはこれ以外を読み込まない

あわせて、置き換わる本文のルール（プロジェクトのタブ、プロジェクト操作の文字ボタン、ステータスの大文字と hover 時の矢印、作成欄の位置、詳細パネルの箱、Done エリアの「箱を使わず」）を新しい形に書き換え、change 名を付ける。絵文字・グラデーション・強い影・中央寄せの禁止は残す。

### 10. 欧文と数字は Inter、和文はシステムフォント

`--font-sans` の先頭に `'Inter'` を足し、続けて今のシステムフォントの並び（`system-ui, -apple-system, 'Segoe UI', 'Hiragino Sans', 'Noto Sans JP', 'Yu Gothic UI', sans-serif`）を残す。Inter には和文の字形が無いので、ブラウザは文字ごとに次のフォントへ代える。欧文・数字（ID、「In Progress」、SP）は Inter、和文はシステムフォントになる。本家 Jira も、和文は Atlassian Sans ではなくシステムフォントで表示しているので、見え方の構図は同じになる。

- 読み込みは `index.html` の `<head>` に Google Fonts の `<link rel="preconnect">` を2つ（`fonts.googleapis.com`、`fonts.gstatic.com` に crossorigin）と、`family=Inter:wght@400;600;700&display=swap` の stylesheet を足す。使う太さは本文 400、ラベル 600、見出し 700 の3つだけ。
- `display=swap` で、読み込むまではシステムフォントで表示し、読み込みに失敗してもシステムフォントのまま使える。
- ID と SP の `tabular-nums` は Inter でも効く（Inter は `tnum` を持つ）。`--font-mono` の ID の等幅表示はそのまま。
- ライセンスは SIL Open Font License 1.1 で、このアプリでの利用に制限は無い。
- 代替案: Inter を npm（`@fontsource/inter`）で同梱する。却下。依存が増え、ビルドの成果物が大きくなる。Google Fonts の配信で足り、失敗してもシステムフォントに戻るだけで困らない。
- 代替案: Atlassian の CDN の woff2 を直接指す。却下。ライセンスの範囲外になる。

## Risks / Trade-offs

- [Google Fonts に届かない環境で欧文の見た目が変わる] → `display=swap` とシステムフォントへのフォールバックで、表示も操作も崩れない。見た目が今のシステムフォントに戻るだけ

- [自作のメニューのキーボード・読み上げの不備] → `Menu` 単体の振る舞い（矢印・Escape・外側クリック・フォーカスの戻り・`aria-checked`/`aria-disabled`）を App.test.tsx のプロジェクトのテストで押さえる。タブ前提の既存テストはこの振る舞いのテストに書き換える
- [タブが無くなりプロジェクトの切り替えが1手増える] → 本家 Jira と同じ手数であり、ユーザーが選んだ方針。選択中のプロジェクトはパンくずと見出しで常に見える
- [飾りのアイコンや角丸が少しずつ増える] → 使ってよいものを例外として列挙し、それ以外は今の原則を残す。`/ui-review --verify jira-like-ui` で確かめる
- [sticky bottom の作成欄が最後の行に重なって見える] → 作成欄は区画の中の最後の要素なので、一覧の末尾までスクロールすると重ならない位置に戻る。白地と上の罫線で行と区別する
- [寒色寄りのトークンでステータスの文字のコントラストが下がる] → 3種のステータスと muted 文字の組み合わせを開発者ツールで 4.5:1 以上に調整してから確定する
- [他の spec に残る「最初のタブのプロジェクト」という言い回し] → per-project-pbi-numbers の pbi-copy・backlog-storage の要件で使われている。意味は「作成した順で最初のプロジェクト」のまま変わらないので、この change では書き換えない

## Migration Plan

データ・URL・保存形式は変えないため、移行の手順は無い。デプロイは通常どおり（GitHub Actions）。戻すときはこの change のコミットを revert すればよい。
