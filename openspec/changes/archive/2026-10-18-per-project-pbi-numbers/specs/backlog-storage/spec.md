# Spec Delta

## MODIFIED Requirements

### Requirement: 共有データへの自動保存
システムは、PBI の作成・編集・削除・並べ替えと、プロジェクトの作成・名前変更・削除のたびに、すべてのプロジェクト（プロジェクトの名前と順序、各プロジェクトの PBI と並び順、各プロジェクトで次に発行する ID 番号）を、すべての端末から読み書きする1つの共有データへ保存 SHALL する。どの端末・ブラウザでアプリを開いても、共有データの同じ内容が表示される。共有データは、アプリの URL を知っている人なら誰でもサインインせずに読み書きできる。共有データの保存先は、アプリが使う1件のデータ以外への読み書きを拒否する。

#### Scenario: 別の端末で開いても同じ内容
- **WHEN** 端末 A のユーザーが PBI を2件作成し、そのあと端末 B のブラウザでアプリを開く
- **THEN** 端末 B に、作成した2件の PBI が同じ ID・内容・順序で表示される

#### Scenario: 再読み込み後もデータが残る
- **WHEN** ユーザーが PBI を2件作成してページを再読み込みする
- **THEN** 作成した2件の PBI が同じ ID・内容・順序で表示される

#### Scenario: 再読み込み後も採番が続く
- **WHEN** あるプロジェクトで `PBI-1`〜`PBI-3` を作成して `PBI-3` を削除し、ページを再読み込みしてからそのプロジェクトで PBI を作成する
- **THEN** 新しい PBI の ID は `PBI-4` になる

#### Scenario: 別の端末でもプロジェクトが同じ
- **WHEN** 端末 A のユーザーがプロジェクト「Tool」を作成して PBI を1件追加し、そのあと端末 B でアプリを開く
- **THEN** 端末 B に「Tool」のタブがあり、その中に追加した PBI が表示される

#### Scenario: 共有データがまだ無い
- **WHEN** 共有データが一度も保存されていない状態でアプリを開く
- **THEN** PBI の無い「マイプロジェクト」1つのバックログが表示され、最初の操作で共有データが作られる

### Requirement: JSON エクスポート
システムは、共有データのすべてのプロジェクトを1つの JSON ファイルとしてダウンロードできる機能を提供 SHALL する。ファイルにはプロジェクトの名前と順序、各プロジェクトの PBI のすべての項目と並び順、各プロジェクトで次に発行する ID 番号、データ形式のバージョンを含める。

#### Scenario: エクスポートする
- **WHEN** プロジェクト「Web」と「Tool」がある状態で、ユーザーがエクスポートを選ぶ
- **THEN** 「Web」と「Tool」の両方とその PBI を含む JSON ファイルがダウンロードされる

### Requirement: JSON インポート
システムは、エクスポートした JSON ファイルを読み込み、確認を経たうえで共有データのすべてのプロジェクトを置き換える機能を提供 SHALL する。置き換えは、共有データを使うすべての端末に反映される。確認では、置き換えられる現在のプロジェクト数と PBI の件数、ファイルに含まれるプロジェクト数と PBI の件数を示し、他の人の画面の内容も置き換わることを示す。インポート後の採番は、プロジェクトごとに、ファイルに含まれるそのプロジェクトの次の ID 番号から続ける。インポート後は、ファイルの最初のプロジェクトを選んだ状態にする。形式が不正なファイルは読み込まず、共有データを変更しない。

#### Scenario: 正しいファイルをインポートする
- **WHEN** ユーザーが、プロジェクト「Web」に `PBI-1` を含み次の番号が 3、「Tool」に `PBI-1` と `PBI-2` を含み次の番号が 3 のファイルを選び、置き換えを確認する
- **THEN** プロジェクトが「Web」と「Tool」に置き換わって「Web」が選ばれ、「Web」で次に作成する PBI の ID は `PBI-3`、「Tool」で次に作成する PBI の ID は `PBI-3` になる

#### Scenario: インポートが他の端末に反映される
- **WHEN** 端末 A のユーザーがファイルをインポートして置き換えを確認する
- **THEN** 端末 B の画面も、ファイルの内容に置き換わる

#### Scenario: 確認で取り消す
- **WHEN** ユーザーがファイルを選んだあと、置き換えの確認で取り消す
- **THEN** 共有データのプロジェクトと PBI は変更されない

#### Scenario: 不正なファイル
- **WHEN** ユーザーが JSON として読めないファイル、必要な項目が欠けたファイル、またはプロジェクトが1つも無いファイルを選ぶ
- **THEN** 読み込めない理由が表示され、共有データは変更されない

#### Scenario: 別々のプロジェクトに同じ番号がある
- **WHEN** ユーザーが、「Web」と「Tool」のどちらにも `PBI-1` を含むファイルを選び、置き換えを確認する
- **THEN** ファイルは読み込まれ、「Web」と「Tool」のそれぞれに `PBI-1` が表示される

#### Scenario: PBI の番号が重複したファイル
- **WHEN** ユーザーが、1つのプロジェクトの中に同じ番号の PBI を2件含むファイルを選ぶ
- **THEN** 番号が重複していることが表示され、共有データは変更されない

### Requirement: 旧形式のデータの読み込み
システムは、プロジェクトの無い旧形式（version 1）と、番号が全プロジェクトの通し番号だった旧形式（version 2）のエクスポートファイル、およびこのブラウザに残ったこれらの形式の以前のデータを読み込める SHALL。

version 1 を読み込むと、すべての PBI を元の並び順のまま1つのプロジェクト「マイプロジェクト」に入れ、PBI の ID と内容、次に発行する ID 番号は変えない。

version 2 を読み込むと、プロジェクトとその順序、PBI の内容と並び順は変えずに、番号を次のように振り直す。最初のプロジェクトの PBI は番号を変えず、そのプロジェクトで次に発行する番号は、ファイルの次に発行する ID 番号とする。2つ目以降のプロジェクトの PBI は、作成日時の古い順（作成日時が同じときは元の番号の小さい順）に `PBI-1` から振り直し、そのプロジェクトで次に発行する番号は、振り直した最大の番号に1を足した値とする。

#### Scenario: 旧形式の保存データで開く
- **WHEN** このブラウザのローカルストレージに `PBI-1`, `PBI-2` を含む旧形式の以前のデータがある状態でページを開く
- **THEN** 以前のデータが残っていることと「1 プロジェクト・2 件」が表示され、共有データは変わらない

#### Scenario: 旧形式のファイルをインポートする
- **WHEN** ユーザーが以前エクスポートした version 1 のファイルを選び、置き換えを確認する
- **THEN** 共有データのすべてのプロジェクトが、ファイルの PBI を持つ「マイプロジェクト」1つに置き換わる

#### Scenario: 通し番号の旧形式のファイルをインポートする
- **WHEN** ユーザーが、「Jisaku-Jira-App」に `PBI-1`〜`PBI-9` と `PBI-11`、「Yarikuri」に `PBI-10` と `PBI-12` を含み次の番号が 13 の version 2 のファイルを選び、置き換えを確認する
- **THEN** 「Jisaku-Jira-App」の PBI は `PBI-1`〜`PBI-9` と `PBI-11` のまま、「Yarikuri」の PBI は作成日時の順に `PBI-1` と `PBI-2` になる。「Jisaku-Jira-App」で次に作成する PBI は `PBI-13`、「Yarikuri」で次に作成する PBI は `PBI-3` になる

## ADDED Requirements

### Requirement: 通し番号の共有データの振り直し
システムは、共有データが番号を全プロジェクトの通し番号で振っていた形式（version 2）のとき、それを読み込んで、「旧形式のデータの読み込み」の version 2 と同じ規則で番号を振り直した内容を表示 SHALL する。振り直した内容は、次に共有データへ保存するときに新しい形式で保存する。振り直しの結果は、どの端末で読み込んでも同じになる。振り直しても、プロジェクトとその順序、PBI の内容と並び順は変わらない。

#### Scenario: 通し番号の共有データで開く
- **WHEN** 共有データが version 2 で、最初のタブの「Jisaku-Jira-App」に `PBI-1`〜`PBI-9`、2つ目のタブの「Yarikuri」に `PBI-10` がある状態でアプリを開き、「Yarikuri」のタブを選ぶ
- **THEN** 「Yarikuri」の一覧には `PBI-10` だった PBI が `PBI-1` として表示され、「Jisaku-Jira-App」の PBI の ID は変わらない

#### Scenario: 振り直したあとに作成する
- **WHEN** 上の状態で、ユーザーが「Yarikuri」で PBI を作成する
- **THEN** 新しい PBI の ID は `PBI-2` になり、共有データは新しい形式で保存される

#### Scenario: どの端末でも同じ番号
- **WHEN** 共有データが version 2 のまま、端末 A と端末 B で同時にアプリを開く
- **THEN** 両方の端末で、同じ PBI に同じ ID が表示される
