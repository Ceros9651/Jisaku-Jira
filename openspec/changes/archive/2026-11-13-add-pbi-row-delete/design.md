# Design

## Context

- 一覧の行は `BacklogTable.tsx` の `RowCells` で描画する。コピーは行の最後の列（`copyCol`）にアイコンのボタンとして置いてあり、狭い画面では CSS Grid の `copy` 領域に並ぶ。
- 詳細パネルの削除は `DetailPanel` の中で `ConfirmDialog` を出し、確定すると `App.tsx` が `dispatch({ type: 'delete', ... })` して `select(null)` でパネルを閉じる。reducer の `delete` は既にあり、変更しない。
- `BacklogTable` は未完了と Done の2か所で使われ、確認ダイアログは `App.tsx` に集まっている（プロジェクト削除など）。
- 行の操作のルール（`docs/design-principles.md`）は「文字のボタン」が原則で、コピーだけが例外のアイコン。

## Goals / Non-Goals

**Goals:**
- 一覧から2操作（ボタン→確認）で削除できる。確認は詳細パネルと同じ文言・同じ部品にする。
- 既存のコピー・選択・並べ替えの挙動を変えない。

**Non-Goals:**
- 元に戻す（Undo）や、複数選択での一括削除。
- 確認の省略。誤クリックの危険が増えるため、確認は必ず出す。
- 詳細パネルの削除ボタンの廃止。

## Decisions

1. **確認ダイアログは `App.tsx` に1つだけ持つ。** 表は `onDelete(number)` を呼ぶだけにし、`App` が削除対象の PBI 番号を持って `ConfirmDialog` を出す。行ごとにダイアログを持たせると、未完了と Done の両方の表と行の数だけ状態が増える。文言は詳細パネルと揃える（「PBI-n を削除しますか？」／「<タイトル>」を削除します。削除した ID は再利用されません。）。重複は小さいので共通化はせず、同じ文字列にとどめる。
2. **削除は新しい列として置く。** `copyCol` の右に `deleteCol` を追加し、ヘッダーには読み上げ用の「削除」を置く。DOM の順はコピーの後ろにして、読み上げ順を保つ。見た目はコピーと同じ 24px 角のボタンで、普段は muted、行 hover・focus で本文色にする。赤（`--danger`）は使わず、危険は確認ダイアログの側で示す（赤は保存失敗などのエラー表示だけ、という既存のルールに従う）。
3. **アイコンはゴミ箱の線画（16px の inline SVG）。** コピーと同じ線の太さ（1.5）と色の扱いにする。名前は「PBI-n を削除」、`title` は「削除」。`docs/design-principles.md` のコピーの例外を「コピーと削除」に広げる形で追記する。
4. **開いている PBI を消したら詳細パネルを閉じる。** 削除の確定処理で、削除した番号が選択中の番号と同じときだけ `select(null)` する。別の PBI を開いているときは何も変えない。詳細パネル経由の削除はこれまでどおり必ず閉じる。
5. **狭い画面は Grid の領域を1つ足す。** 2段目の列と領域を `type id status points copy delete .` にし、`delete` 領域を足す。間隔は既存の 8px の `column-gap` に従う。
6. **ボタンのクリックは選択に伝えない。** 選択はタイトルのボタンだけが担当しており、コピーと同様に行のクリックでは選択されない。削除ボタンも同じ構造で、追加の `stopPropagation` は不要。

**代替案:** 文字の「削除」ボタンを行に置く案は、狭い画面で2段目が窮屈になり、コピーと並びが揃わないため採らない。行ごとの「…」メニューに入れる案は、すぐ届かないという課題を解決しないため採らない。

## Risks / Trade-offs

- [誤クリックで消す] → 必ず確認ダイアログを挟む。コピーのすぐ隣にあるが、アイコンの形が違い（四角2つ／ゴミ箱）、24px 角のボタンの間に 8px 前後の間隔を保つ。
- [スマホで押し間違える] → 2段目で詰めて並ぶが、ボタンは 24px 角、間隔は 8px を保つ。実画面（390px 幅）で確認する。
- [確認を開いている間に PBI が消える（他の端末の同期など）] → reducer の削除は存在しない番号を無視するだけで壊れない。実装時にテストで確認する。
