# Design

## Context

- `index.html` は `<link rel="icon" href="data:," />` で空のアイコンを指定している。タブには何も出ないが、お気に入りではブラウザが同じオリジン（`ceros9651.github.io`）で覚えているアイコンを使うことがあり、同じ GitHub Pages アカウントで公開している Yarikuri（`/Yarikuri/favicon.ico` などを指定）のアイコンが出る。
- ドメイン直下の `https://ceros9651.github.io/favicon.ico` は 404（ユーザーサイトのリポジトリが無い）。このリポジトリからドメイン直下にファイルは置けない。
- Vite の `base` は `/Jisaku-Jira/`。`public/` ディレクトリはまだ無い。デプロイは `.github/workflows/deploy.yml` で `dist/` をそのまま GitHub Pages に上げる。
- アクセント色は `--accent: #1f5fbf`（`src/styles/tokens.css`）。デザイン方針では飾りアイコンを避け、グラデーションや強い影を使わない。

## Goals / Non-Goals

**Goals:**
- タブ・お気に入り・iOS ホーム画面で、このアプリ専用のアイコンが出る。
- ビルドに追加の依存を入れない。

**Non-Goals:**
- PWA 化（manifest や Service Worker）。ホーム画面に追加したときの起動画面やオフライン対応は扱わない。
- 画面内（ヘッダーなど）にロゴを表示すること。
- すでにブラウザに保存されたお気に入りのアイコンを、利用者側の操作なしに書き換えること。

## Decisions

### 図柄: 3 列のボードに縦長の札が並ぶ形
アクセント色（`#1f5fbf`）の角丸の正方形の地に、白い縦の札（カード）を 3 列、高さを変えて並べる。Jira のバックログ／ボードを連想させ、16px でも「列に札が並んだもの」と読める。
- 代替案: チケット（半券の切り欠き付き）の形。16px では切り欠きがつぶれて単なる長方形に見えるため採らない。
- 代替案: 「J」などの文字。チケット管理ツールであることが伝わらない（受け入れ条件を満たさない）ため採らない。
- 色はアクセント色と白の 2 色だけにし、グラデーションと影は付けない（デザイン方針に合わせる）。

### ファイルの置き場所と形式
`public/` に次を置き、`index.html` から `%BASE_URL%`（Vite が `/Jisaku-Jira/` に置き換える）付きで指定する。
- `icon.svg`: 主のアイコン（`<link rel="icon" type="image/svg+xml">`）。手書きの SVG。
- `favicon-32.png`（32×32）: SVG アイコンを使わない環境向け（`<link rel="icon" type="image/png" sizes="32x32">`）。Safari のお気に入りなど。
- `apple-touch-icon.png`（180×180）: iOS のホーム画面用（`<link rel="apple-touch-icon">`）。角丸は iOS が付けるので、地は四角いまま塗る。
- 代替案: `favicon.ico`。多サイズ ICO の作成に専用ツールが要り、PNG で現行ブラウザは足りるため採らない。
- PNG は SVG から一度だけ書き出してリポジトリに置く（ビルド時の生成はしない）。書き出しには開発環境のブラウザ（Playwright など）や手元のツールを使い、依存パッケージには加えない。

### 指定の書き方
`<link>` の `href` は `%BASE_URL%icon.svg` のように Vite の置換を使い、`base` を変えても追従させる。ビルド後の `dist/index.html` で `/Jisaku-Jira/icon.svg` になっていることを確認する。

## Risks / Trade-offs

- [ブラウザがお気に入りのアイコンを古いまま持ち続ける] → 新しいアイコンを配信しても、既存のお気に入りは一度ページを開き直すまで（ブラウザによっては削除して追加し直すまで）Yarikuri のアイコンのままのことがある。確認手順にお気に入りの追加し直しを含める。
- [16px での判別] → 3 列の札の幅と隙間を 16px のグリッドで整数ピクセルに合わせて描き、実際に 16px で表示して確認する。
- [テストで担保しにくい] → 単体テストで `index.html` のアイコン指定（`data:,` が無いこと、`%BASE_URL%` を使っていること）と `public/` のファイルの存在を確認し、見た目はデプロイ後に手で確認する。

## Migration Plan

`dev` に push すると既存のワークフローでデプロイされる。戻すときは `index.html` の変更を戻すだけでよい（`public/` のファイルは残っても害はない）。
