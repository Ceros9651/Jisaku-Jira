# Proposal

## Why

いまのバックログは1つだけで、別々のプロダクト（個人開発のアプリ、ツールなど）の PBI が1本の一覧に混ざる。並び順や SP の合計もプロダクトをまたいで計算されるため、優先順位を付けにくい。プロジェクトごとにバックログを分け、画面上部のタブで切り替えられるようにする。

## What Changes

- バックログを「プロジェクト」単位に分ける。PBI は必ずどれか1つのプロジェクトに属し、一覧・件数・SP 集計・並べ替えは選んでいるプロジェクトの中だけで行う。
- ヘッダーの下にプロジェクトのタブを並べる。タブを押すとそのプロジェクトのバックログに切り替わる。最後に開いていたプロジェクトを覚え、次に開いたときもそのプロジェクトを表示する。
- プロジェクトは作成・名前変更・削除ができる。削除は確認を経て、そのプロジェクトの PBI もまとめて消える。プロジェクトは常に1つ以上あり、最後の1つは削除できない。
- PBI の ID（`PBI-<番号>`）は今までどおり全プロジェクトで通し番号にする。プロジェクトを削除しても番号は再利用しない。
- `#PBI-<番号>` のリンクは形を変えない。開くと、その PBI が属するプロジェクトのタブが選ばれた状態で詳細パネルが開く。
- 保存データとエクスポートファイルの形式を、プロジェクトを持つ新しい形式（version 2）に変える。**BREAKING**: 新しい形式のファイルは、この change より前のアプリでは読み込めない。
- 既存の保存データと、以前エクスポートしたファイル（version 1）はそのまま読み込める。読み込むと、全 PBI を1つのプロジェクト「マイプロジェクト」に入れた形になる。
- エクスポート・インポートは全プロジェクトまとめて1ファイルで行う。インポートは全プロジェクトを置き換える。
- 今回入れないもの: PBI を別のプロジェクトへ移すこと、プロジェクトの並べ替え、プロジェクト単位のエクスポート、コピーする Markdown へのプロジェクト名の追加。

## Capabilities

### New Capabilities

- `projects`: プロジェクトのタブ表示と切り替え、作成・名前変更・削除、最後に開いていたプロジェクトの記憶

### Modified Capabilities

- `pbi-backlog`: PBI の作成先が選択中のプロジェクトになる。採番が全プロジェクトの通し番号であることを明記する。一覧・件数・合計・並べ替えが選択中のプロジェクトの範囲になる。
- `backlog-storage`: 保存とエクスポートの対象が全プロジェクトになる。インポートが全プロジェクトを置き換える。旧形式（version 1）のデータとファイルの読み込みを追加する。
- `pbi-copy`: PBI のリンクを開くと、その PBI のプロジェクトに切り替わる。

## Impact

- 変えるファイル:
  - src/backlog/model.ts（プロジェクトの型、データ形式 version 2）、reducer.ts（プロジェクトの作成・名前変更・削除、PBI の操作をプロジェクト単位に）、validate.ts（version 2 の検証と version 1 からの変換）、storage.ts（最後に開いたプロジェクトの記憶）
  - src/App.tsx と App.module.css（タブ、プロジェクトの操作、選択中のプロジェクトでの絞り込み）
  - 新規コンポーネント src/components/ProjectTabs.tsx とその CSS
- 保存データ: localStorage の同じキーに、初回の保存で version 2 として書き直す。書き直した後は、この change より前のアプリでは読めない。
- テスト: reducer・validate・storage の単体テストと App.test.tsx を、プロジェクトのあるデータに合わせて直し、タブの操作と version 1 の読み込みのテストを足す。
- docs: README のデータの保存とバックアップの節にプロジェクトのことを足す。docs/design-principles.md にタブの見た目のルールを足す。
