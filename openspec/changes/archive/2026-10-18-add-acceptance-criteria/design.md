# Design

## Context

- 共有データは Firestore の `backlogs/shared` 1件に、エクスポートと同じ JSON 文字列（`version: 2`）で置いている。Firestore のルールは `json` が文字列であることしか見ないので、PBI の項目を足してもルールは変わらない。
- 読み込みはすべて `validate.ts` の `validateItems` を通る。ここは知っている項目だけを取り出して `Pbi` を作り直すので、知らない項目は捨てられる。
- 書き込みは `remote.ts` の `nextBacklog` が、共有データの最新の JSON を検証してから操作を当て直す。つまり各クライアントは、保存のたびに自分の知っている項目だけで PBI を作り直して書く。
- 詳細パネル（`DetailPanel.tsx`）は、タイトル・説明・SP を下書きとして持ち、`dirty` のときだけ保存ボタンを押せるようにしている。

## Goals / Non-Goals

**Goals:**
- 既存データをそのまま読める形で、`Pbi` に受入条件の文字列を1つ足す。
- 詳細パネルとコピーの Markdown の両方に出す。

**Non-Goals:**
- 一覧の行に受入条件を出すこと、受入条件の有無の表示。
- 作成欄から受入条件を入力すること（作成欄はタイトルだけの1行のまま）。
- Markdown のプレビューやチェックリストとしての達成管理。

## Decisions

### 項目名は `acceptanceCriteria: string`、空は `''`
`description` と同じ扱いにそろえる。未設定を `null` にすると、入力欄・コピー・検証で空文字との二重の扱いが要るので、空は `''` に統一する。配列（1条件1要素）はユーザーの選択どおり採らない。

### データ形式のバージョンは 2 のまま、欠けていたら `''` で補う
`validateItems` で `acceptanceCriteria` が `undefined` なら `''` にし、文字列以外なら「`<n> 件目の acceptanceCriteria が文字列ではありません`」で落とす。version 1 の変換も同じ `validateItems` を通るので、追加の処理は要らない。
- 代わりに version 3 を切る案: 旧版のクライアントが version 3 を「対応していない形式」として読めなくなり、移行の仕組みも要る。項目の追加は後方互換なので切らない。

### reducer は `description` と同じ道を通す
`PbiChanges` に `acceptanceCriteria` を加え、`applyChanges` で文字列ならそのまま入れる。`create` は `acceptanceCriteria: ''` で作る（作成欄からは渡さないので、`create` のアクションには足さない）。

### 詳細パネルは説明の直下に同じ形の textarea を置く
ラベル「受入条件」、`description` と同じ class（枠・角丸 4px・`resize: vertical`）で、行数は説明より少ない `rows={6}`。下書きの state と `dirty` の判定、`onSave` に渡す変更に足す。デザイン方針の「項目はラベル左・値右の行」はステータスと SP の短い値の行の話で、説明と同じく長文の欄はラベルを上に置く。新しい色・アイコン・箱は足さない。

### コピーは説明の後ろに同じ形で足す
`formatPbiMarkdown` で、説明と同じく `trim()` して空なら「（なし）」。既存の説明も `trim()` しているので、spec の文言を実装に合わせて「前後の空白を除いて」とした。

## Risks / Trade-offs

- [デプロイ直後に古い版を開いたままのタブが保存すると、その版の `validateItems` が受入条件を捨てて書き戻し、全 PBI の受入条件が消える] → 個人利用で同時に開く端末は少ない。デプロイ後は開いているタブを再読み込みする旨を PR に書く。受入条件が書かれるのはデプロイ後なので、移行の瞬間に失うデータは無い。
- [JSON が少し大きくなる] → Firestore ルールの上限は 900,000 文字で、今の規模では問題にならない。

## Migration Plan

- データの変換作業は無い。読み込み時に補うだけ。
- ロールバックしても、旧版は受入条件を捨てて読むだけで壊れない（その時点で書かれた受入条件は、次の保存で消える）。
