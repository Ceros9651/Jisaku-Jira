# Proposal

## Why

バックログの一覧はタイトルを読まないと PBI の種類（新しい作業か、不具合の修正か、テストか、運用作業か）が分からない。一覧を見た瞬間に何の PBI かを見分けられるよう、PBI にカテゴリを持たせ、一覧の ID の左にカテゴリごとに見分けのつくアイコンを出す。カテゴリは作ったあとで付け直すのではなく、作成欄で入力するときに指定できるようにする。（PBI-9）

## What Changes

- PBI に「カテゴリ」の項目を足す。値は `タスク`・`バグ`・`テスト`・`運用` の4つのいずれかで、必ずどれか1つを持つ。
- 一覧の各行で、並べ替えの持ち手と ID のあいだにカテゴリのアイコンを表示する。アイコンはカテゴリごとに色と形の両方を変えた小さな四角にし、読み上げと hover ではカテゴリ名が分かるようにする。
- 作成欄のタイトル入力の左にカテゴリの選択を置き、選んだカテゴリで PBI を作る。初期値は `タスク` で、作成後も直前に選んだカテゴリを残す（同じ種類を続けて入力しやすくするため）。
- 詳細パネルでもカテゴリを表示・変更できるようにする。
- コピーする Markdown の箇条書きに「- カテゴリ: <名前>」の行を足す。
- 保存データ・エクスポートファイルにカテゴリを含める。カテゴリを持たない既存の PBI（今の共有データ、以前のエクスポートファイル、version 1 のデータ）は `タスク` として読み込む。データ形式の version は 2 のまま変えない。
- `docs/design-principles.md` の「色を使うのはステータス表示だけ」「飾りのアイコンは使わない」に、カテゴリのアイコンを例外として追記する（カテゴリは文字の列を足さずに一目で見分けることが目的のため、アイコンと色が機能を持つ）。

## Capabilities

### New Capabilities

（なし）

### Modified Capabilities

- `pbi-backlog`: PBI の作成でカテゴリを指定できる。一覧の各行にカテゴリのアイコンを表示する。詳細パネルでカテゴリを表示・編集できる。カテゴリの値の範囲を定める要件を足す。
- `pbi-copy`: コピーする Markdown にカテゴリの行を足す。
- `backlog-storage`: 保存・エクスポートにカテゴリを含め、カテゴリの無い PBI を `タスク` として読み込む。

## Impact

- データ: `src/backlog/model.ts`（`Category` 型・ラベル・`Pbi.category`）、`src/backlog/validate.ts`（カテゴリの検証と既定値）、`src/backlog/reducer.ts`（`create` と `update` のカテゴリ）、`src/backlog/share.ts`（Markdown）。
- 画面: `src/components/BacklogTable.tsx`・`CreatePbiForm.tsx`・`DetailPanel.tsx` と各 CSS、`src/App.tsx`（作成時にカテゴリを渡す）、`src/styles/tokens.css`（カテゴリの色）。新しいコンポーネントとしてカテゴリのアイコンと選択を足す。
- 共有データ（Firestore `backlogs/shared`）: JSON の中身が増えるだけで、ルールと保存先は変わらない。この変更の前のアプリを開いたままのタブが保存すると、そのタブはカテゴリを知らないため検証で落とし、カテゴリが消えて `タスク` に戻る可能性がある（再読み込みで解消）。
- ドキュメント: `docs/design-principles.md`、README の機能一覧。
- 依存ライブラリの追加はない。
