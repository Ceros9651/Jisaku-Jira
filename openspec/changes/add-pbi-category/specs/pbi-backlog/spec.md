# Spec Delta

## ADDED Requirements

### Requirement: カテゴリ
PBI のカテゴリは `タスク`、`バグ`、`テスト`、`運用` のいずれかで SHALL ある。すべての PBI はカテゴリをちょうど1つ持つ。カテゴリを持たないデータから読み込んだ PBI は `タスク` とする。

#### Scenario: 4つのカテゴリから選べる
- **WHEN** ユーザーが作成欄または詳細パネルでカテゴリの選択肢を開く
- **THEN** 選択肢は `タスク`・`バグ`・`テスト`・`運用` の4つだけで、空（未設定）の選択肢は無い

### Requirement: 一覧のカテゴリのアイコン
システムは、一覧の各行で、並べ替えの持ち手と ID のあいだに、その PBI のカテゴリを示すアイコンを表示 SHALL する。アイコンは4つのカテゴリで色と形の両方が異なり、色を見分けられなくても形で区別できる。アイコンには文字を添えないが、読み上げではカテゴリ名（例: 「バグ」）として識別でき、ポインターを重ねるとカテゴリ名が表示される。一覧の見出しの行にはカテゴリの列の見出しを文字で表示しない。

#### Scenario: 行にカテゴリのアイコンが出る
- **WHEN** `PBI-1` のカテゴリが `タスク`、`PBI-2` のカテゴリが `バグ` の一覧を見る
- **THEN** 各行の ID の左にアイコンが表示され、`PBI-1` と `PBI-2` のアイコンは色と形が異なる

#### Scenario: 読み上げでカテゴリが分かる
- **WHEN** スクリーンリーダーで `PBI-2`（カテゴリ `バグ`）の行を読む
- **THEN** ID の前に「バグ」と読み上げられる

## MODIFIED Requirements

### Requirement: PBI の作成
システムは、タイトルを入力して PBI を作成できる機能を提供 SHALL する。タイトルは前後の空白を除いて1文字以上でなければならない。作成欄では、タイトルの入力の左でカテゴリを選べる。カテゴリの初期値は `タスク` で、作成したあとも直前に選んだカテゴリを選んだままにする。説明とストーリーポイントは任意とする。作成された PBI のステータスは `To Do` とし、選んでいるプロジェクトのバックログの末尾に追加する。

#### Scenario: タイトルだけで作成する
- **WHEN** ユーザーがカテゴリを変えずに、タイトル「ログイン画面を作る」を入力して作成する
- **THEN** 選んでいるプロジェクトのバックログの末尾に、タイトル「ログイン画面を作る」、カテゴリ `タスク`、ステータス `To Do`、説明とストーリーポイントが空の PBI が追加される

#### Scenario: カテゴリを指定して作成する
- **WHEN** ユーザーが作成欄でカテゴリを `バグ` にし、タイトル「保存に失敗する」を入力して作成する
- **THEN** カテゴリ `バグ` の PBI「保存に失敗する」が末尾に追加され、一覧の行にバグのアイコンが表示される

#### Scenario: 続けて作成するとカテゴリが残る
- **WHEN** ユーザーがカテゴリ `バグ` で PBI を作成し、そのまま次のタイトルを入力して作成する
- **THEN** 作成欄のカテゴリは `バグ` のままで、2件目もカテゴリ `バグ` で作成される

#### Scenario: タイトルが空のときは作成しない
- **WHEN** ユーザーがタイトルを空、または空白だけにして作成しようとする
- **THEN** PBI は作成されず、タイトルが必要であることが表示される

#### Scenario: 他のプロジェクトには追加されない
- **WHEN** プロジェクト「Web」と「Tool」があり、「Tool」を選んでいる状態で PBI を作成する
- **THEN** PBI は「Tool」の一覧にだけ表示され、「Web」の一覧には表示されない

### Requirement: バックログ一覧の表示
システムは、選んでいるプロジェクトのすべての PBI をバックログの並び順で一覧表示 SHALL する。各行にはカテゴリのアイコン、ID、タイトル、ステータス、ストーリーポイントを表示する。一覧の見出しにはプロジェクトの名前を表示し、その上部には選んでいるプロジェクトの PBI の件数とストーリーポイントの合計を表示する。

#### Scenario: 一覧を開く
- **WHEN** ユーザーがバックログ画面を開く
- **THEN** 選んでいるプロジェクトのすべての PBI がバックログの並び順で、カテゴリのアイコン・ID・タイトル・ステータス・ストーリーポイントとともに表示される

#### Scenario: 件数と合計
- **WHEN** 選んでいるプロジェクトにストーリーポイント 3、5、未設定の PBI が3件あり、他のプロジェクトに SP 8 の PBI が1件ある
- **THEN** 一覧の上部に件数 3 とストーリーポイント合計 8 が表示される

#### Scenario: PBI がないとき
- **WHEN** 選んでいるプロジェクトに PBI が1件もない
- **THEN** PBI がないことと、PBI を作成する操作が表示される

### Requirement: PBI の詳細表示と編集
システムは、PBI を選択するとその ID、タイトル、カテゴリ、説明、ステータス、ストーリーポイントを表示し、ID 以外の項目を編集できるように SHALL する。編集でもタイトルは前後の空白を除いて1文字以上でなければならない。

#### Scenario: タイトルと説明を編集する
- **WHEN** ユーザーが `PBI-2` を開き、タイトルと説明を変更して保存する
- **THEN** `PBI-2` のタイトルと説明が更新され、ID とバックログ上の位置は変わらない

#### Scenario: カテゴリを変更する
- **WHEN** ユーザーがカテゴリ `タスク` の `PBI-2` を開き、カテゴリを `運用` に変更して保存する
- **THEN** `PBI-2` のカテゴリが `運用` になり、一覧の行のアイコンが運用のアイコンに変わる。ID とバックログ上の位置は変わらない

#### Scenario: タイトルを空にして保存しようとする
- **WHEN** ユーザーが編集中にタイトルを空にして保存しようとする
- **THEN** 変更は保存されず、タイトルが必要であることが表示される
