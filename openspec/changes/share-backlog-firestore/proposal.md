# Proposal

## Why

いまのデータは使っているブラウザの localStorage にだけあり、別の端末やブラウザから開くと空のバックログが出る。複数人がそれぞれの端末から同じバックログを見て更新できるよう、データを1か所（Firebase Firestore）に置き、どの端末で開いても同じ内容が表示されるようにする（PBI-4）。

## What Changes

- バックログ（全プロジェクト・PBI・採番）の保存先を、ブラウザの localStorage から Firestore の共有データ1件に変える。どの端末・ブラウザで開いても同じ内容が表示される。
- 他の端末での変更は、開いている画面に再読み込みなしで反映される。
- 同時に操作しても、別々の PBI やプロジェクトへの変更は両方残る。PBI の番号は同時に作成しても重複しない。同じ PBI の同じ項目を同時に変えたときは、後から保存したほうが残る。
- 起動時は共有データを読み込むまで「読み込み中」を表示する。接続できないとき、保存に失敗したときは、そのことを表示する。
- サインインは設けない。**アプリの URL を知っている人は誰でも閲覧・編集・削除できる**（ユーザーの判断）。Firestore のセキュリティルールは、決まった1件のデータの読み書きだけを許し、それ以外を拒否する。
- エクスポート・インポートは残す。インポートは共有データ全体を置き換え、全員の画面に反映される。
- このブラウザの localStorage に以前のデータが残っているときは、そのことを表示し、共有データへの取り込み（インポートと同じ確認つき）、ファイルへの書き出し、このブラウザからの削除を選べるようにする。自動では取り込まない。
- `#PBI-<番号>` のリンクは、どの端末で開いてもその PBI の詳細が開くようになる。
- 最後に開いていたプロジェクトの記憶は、今までどおりブラウザごとに持つ（共有しない）。
- **BREAKING**: アプリを動かすには Firebase プロジェクトと、その接続設定（ビルド時の環境変数）が必要になる。設定が無いビルドは、接続先が無いことを表示して使えない。
- 今回入れないもの: サインインと権限管理、オフラインでの編集、変更履歴・元に戻す、誰が編集中かの表示、同じ PBI の編集の衝突の検出。

## Capabilities

### New Capabilities

- `backlog-sync`: 他の端末での変更のリアルタイムな反映、同時操作の扱い、読み込み中と接続エラーの表示

### Modified Capabilities

- `backlog-storage`: 保存先をブラウザから共有データに変える。保存失敗・読めない共有データの扱いを共有データ向けにする。インポートが共有データを置き換える。localStorage に残った以前のデータ（version 1 を含む）の取り込みを追加する。
- `projects`: 初めて開いたときの条件を「共有データが無いとき」にする。最後に開いていたプロジェクトの記憶がブラウザごとであることを明記する。
- `pbi-copy`: PBI のリンクを別の端末で開いても、その PBI が開くようになる。

## Impact

- 依存: `firebase`（Firestore の Web SDK）を追加する。
- 変えるファイル:
  - src/backlog/useBacklog.ts（共有データの購読と、操作をトランザクションで反映する形に変える）、storage.ts（バックログの保存・読み込みを外し、以前のデータの読み出し・削除と、プロジェクトの記憶だけ残す）
  - 新規 src/backlog/remote.ts（Firestore の読み書きの窓口）、src/backlog/firebase.ts（接続設定）
  - src/App.tsx と App.module.css（読み込み中・接続エラー・保存失敗・以前のデータの表示）
- 新規: firestore.rules、firebase.json（ルールのデプロイ用）、.env.example
- CI: .github/workflows/deploy.yml のビルドに Firebase の設定値（リポジトリの Variables）を渡す。
- 手作業: Firebase プロジェクトの作成、Firestore の有効化、ルールのデプロイ、GitHub の Variables の登録（README に手順を書く）。
- テスト: Firestore を差し替えられるようにし、単体テストと App.test.tsx は偽の共有データで動かす。
- docs: README の「データの保存とバックアップ」を共有データの説明に書き換え、誰でも編集できる点とバックアップの勧めを明記する。
