## MODIFIED Requirements

### Requirement: PBI の削除
システムは、確認を経たうえで PBI を削除できる機能を提供 SHALL する。削除は、詳細パネルの「削除」と、一覧の各行（未完了の一覧と Done エリアの両方）の削除ボタンのどちらからでもできる。一覧の削除ボタンは、文字ではなくゴミ箱の線画のアイコンで表示し、読み上げでは「PBI-<番号> を削除」として識別できるようにする。ポインタを重ねたときのツールチップには「削除」と表示する。どちらの操作でも同じ確認（「PBI-<番号> を削除しますか？」）を表示し、削除を選んだときだけ削除する。削除した PBI は一覧から消え、他の PBI の ID と並び順は変わらない。一覧の削除ボタンを押しても PBI の選択は変わらず、詳細パネルは開かない。ただし、開いている詳細パネルの PBI を削除したときは、詳細パネルを閉じる。

#### Scenario: 確認して削除する
- **WHEN** ユーザーが `PBI-2` の削除を選び、確認で削除を選ぶ
- **THEN** `PBI-2` が一覧から消え、残りの PBI は元の順序のまま表示される

#### Scenario: 確認で取り消す
- **WHEN** ユーザーが `PBI-2` の削除を選び、確認で取り消す
- **THEN** `PBI-2` は削除されない

#### Scenario: 一覧から削除する
- **WHEN** 詳細パネルを閉じた状態で、ユーザーが一覧の `PBI-2` の行の削除ボタンを押し、確認で削除を選ぶ
- **THEN** `PBI-2` が一覧から消え、残りの PBI は元の順序のまま表示され、詳細パネルは閉じたままになる

#### Scenario: 一覧の削除を確認で取り消す
- **WHEN** ユーザーが一覧の `PBI-2` の行の削除ボタンを押し、確認で取り消す
- **THEN** `PBI-2` は削除されず、確認は閉じる

#### Scenario: 削除ボタンを押しても詳細パネルは開かない
- **WHEN** 詳細パネルを閉じた状態で、ユーザーが一覧の `PBI-2` の行の削除ボタンを押す
- **THEN** 「PBI-2 を削除しますか？」の確認が表示され、詳細パネルは開かず、URL のハッシュも変わらない

#### Scenario: Done の PBI を一覧から削除する
- **WHEN** Done エリアに `PBI-5` がある状態で、ユーザーがその行の削除ボタンを押し、確認で削除を選ぶ
- **THEN** `PBI-5` が Done エリアから消える

#### Scenario: 開いている PBI を一覧から削除する
- **WHEN** `PBI-2` の詳細パネルを開いた状態で、ユーザーが一覧の `PBI-2` の行の削除ボタンを押し、確認で削除を選ぶ
- **THEN** `PBI-2` が一覧から消え、詳細パネルが閉じる

#### Scenario: 別の PBI を開いたまま削除する
- **WHEN** `PBI-1` の詳細パネルを開いた状態で、ユーザーが一覧の `PBI-2` の行の削除ボタンを押し、確認で削除を選ぶ
- **THEN** `PBI-2` が一覧から消え、`PBI-1` の詳細パネルは開いたままになる

#### Scenario: 削除ボタンはアイコンで表示される
- **WHEN** ユーザーが一覧を見る
- **THEN** 各行の削除ボタンは文字ではなくゴミ箱のアイコンで表示され、読み上げでは「PBI-1 を削除」と識別でき、ツールチップは「削除」になる

### Requirement: 一覧の行の表示
システムは、一覧の各行を、並べ替えの持ち手（未完了の一覧だけ）、PBI のカテゴリを示すアイコン、ID、タイトル、ステータス、ストーリーポイント、コピー、削除の順で表示 SHALL する。カテゴリのアイコンは「一覧のカテゴリのアイコン」のとおりに表示する。ストーリーポイントは、数字を灰色の小さなバッジで右揃えに表示し、未設定のときはバッジに「-」を表示して、読み上げでは「未設定」と伝える。`Done` の PBI の行は ID に取り消し線を引く。タイトルが長いときは1行に収めて末尾を省略する。

#### Scenario: SP が未設定の行
- **WHEN** 一覧に SP が未設定の PBI がある
- **THEN** その行の SP の位置に「-」のバッジが表示される

#### Scenario: Done の行の ID
- **WHEN** Done エリアに `PBI-2` がある
- **THEN** Done エリアの `PBI-2` の行の ID「PBI-2」に取り消し線が引かれ、未完了の一覧の行の ID には取り消し線が引かれない

### Requirement: 狭い画面の一覧の行
システムは、画面の幅が 560px 以下のとき、一覧の各行を2段で表示 SHALL する。1段目にタイトルを、並べ替えの持ち手を除いた行の幅いっぱいに表示し、2段目にカテゴリのアイコン・ID・ステータス・ストーリーポイント・コピー・削除を並べる。読み上げの順は、幅によらずカテゴリ、ID、タイトル、ステータス、ストーリーポイント、コピー、削除の順のまま変えない。一覧の文字は 12px 未満にしない。

#### Scenario: スマホでタイトルが読める
- **WHEN** 390×844 の画面で一覧を開く
- **THEN** 「PBI 一覧の API を作る」が省略されずに1段目に表示され、その下の段にカテゴリのアイコン、「PBI-1」、ステータス、SP、コピー、削除が並ぶ

#### Scenario: デスクトップは1段のまま
- **WHEN** 1440×900 の画面で一覧を開く
- **THEN** 各行は1段で表示される

### Requirement: 行の右側の項目の並び
システムは、一覧の行のステータス・ストーリーポイント・コピーのアイコン・削除のアイコンを互いに 8px 前後の間隔で詰めて並べ、その間隔をステータスの種類によらず一定に表示 SHALL する。1段の行では4つを行の右端に右揃えでまとめ、幅 560px 以下の2段の行では2段目の ID の後ろに左から並べる。

#### Scenario: ステータスと SP の間隔が揃う
- **WHEN** 1440×900 の画面で、「In Progress」の行と「To Do」の行が並んだ一覧を見る
- **THEN** どちらの行も、ステータスのラベルの右端から SP のバッジの左端までの距離が同じになる

#### Scenario: SP とコピーの間を詰める
- **WHEN** 1440×900 の画面で一覧を見る
- **THEN** どの行も、SP のバッジの右端からコピーのアイコンの左端までが 8px 前後になる

#### Scenario: コピーと削除の間を詰める
- **WHEN** 1440×900 の画面で一覧を見る
- **THEN** どの行も、コピーのアイコンの右端から削除のアイコンの左端までが 8px 前後になり、押す範囲（24px 角）は重ならない

#### Scenario: スマホの2段目でも間隔が揃う
- **WHEN** 390×844 の画面で、「In Progress」の行と「To Do」の行が並んだ一覧を見る
- **THEN** どちらの行も、2段目でステータス・SP・コピー・削除が ID の後ろに左から並び、ステータスの右端から SP のバッジの左端までの距離が同じになる
