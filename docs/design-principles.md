# デザイン方針

このアプリのUIで守るルール。/ui-review で採用した修正方針がここに蓄積される。
新しい画面やコンポーネントを作るときも、このファイルに従うこと。

- ルールは「何をどうするか」を一行で書く（例: 一覧の区切りはカードではなく1pxの罫線）。
- 各ルールの末尾に由来の change 名を付ける。
- 例外を作るときは、ルールを消さずに例外として追記する。

## 形と区切り

- バックログ一覧は表形式にし、行の区切りは 1px の罫線にする。行をカードで包まない。（add-pbi-backlog）
- 箱（枠線＋背景）で囲むのは詳細パネル・確認ダイアログ・警告帯のように、一覧と区別して操作する塊だけにする。（add-pbi-backlog）
- 角丸は入力欄・ボタン・ステータスの選択が 4px、パネルとダイアログが 6px。一覧の行と表には付けない。（add-pbi-backlog）
- 影は実際に上に重なるもの（ダイアログ、ドラッグ中の行）だけに付ける。（add-pbi-backlog）
- 作成欄は一覧の行と同じ高さの罫線の行にし、塗りつぶしたボタンを置かない。（ui-refine-backlog）


## 色と階層

- 色は無彩色の段階（`--gray-*`）を主にし、アクセント色は1色（`--accent`）だけにする。（add-pbi-backlog）
- アクセント色を使うのは主ボタン、選択中の行、フォーカスリング、リンクだけ。（add-pbi-backlog）
- ステータスは文字ラベル（To Do / In Progress / Done）で区別し、色は補助にとどめる。色を使うのはステータス表示だけ。（add-pbi-backlog）
- 警告とエラーの赤・黄は、保存失敗・読み込みエラー・入力エラーの表示にだけ使う。（add-pbi-backlog）
- 階層は影ではなく、背景の明度差と罫線で示す。グラデーションは使わない。（add-pbi-backlog）
- ステータスは文字幅に合わせた Lozenge（薄い背景＋大文字の短いラベル）で表し、一覧と詳細パネルで同じ見た目にする。変更の手がかりの矢印は hover・focus のときだけ出す。（ui-refine-backlog）
- 一覧の見出しの集計には、ステータス別の SP をステータスと同じ色の小さなバッジで並べ、集計の文字は本文に近い濃さ（gray-700）にする。（ui-refine-backlog）


## アイコンと文字

- 飾りのアイコンと絵文字は使わない。並べ替えの持ち手（⋮⋮ 相当の線画）のように、文字なしで機能するものだけを使う。（add-pbi-backlog）
- ID とストーリーポイントは等幅数字（`font-variant-numeric: tabular-nums`）にする。ストーリーポイントは右揃え。（add-pbi-backlog）
- 文字サイズは 12 / 13 / 14 / 18px の4段階。いちばん大きいのは画面見出し。（add-pbi-backlog）
- 行の操作（コピーなど）はアイコンではなく文字のボタンにし、普段は muted、行 hover・focus で本文色と下線にする。タッチ端末でも押せるよう、hover だけで出し入れしない。（add-pbi-copy-link）

## 余白とレイアウト

- 画面は左揃え。一覧を左、詳細パネルを右に並べる（Jira のバックログと同じ配置）。中央寄せのランディング構成にしない。（add-pbi-backlog）
- 件数とストーリーポイント合計は一覧の見出しの行に置く。（add-pbi-backlog）
- 余白は 4 / 8 / 12 / 16 / 24 / 32px の段階から選び、関係の近い要素は詰め、区切りたいところを広げる。一覧の行は詰めて表示する。（add-pbi-backlog）
- 空状態はイラストを使わず、短い文と作成の操作だけを示す。（add-pbi-backlog）
- バックログ一覧はコンテンツ領域の幅いっぱいに広げ、固定の最大幅を付けない。（ui-refine-backlog）
- 詳細パネルの先頭は ID と、枠の無い見出しに見えるタイトルにし、入力欄の枠は hover・focus のときだけ出す。項目はラベル左・値右の行で並べる。（ui-refine-backlog）
